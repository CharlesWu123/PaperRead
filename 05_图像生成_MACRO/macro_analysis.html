MACRO: Advancing Multi-Reference Image Generation with Structured Long-Context Data

HKU MMLab / Meituan
arXiv:2603.25319v1, March 2026
代码状态：未公开代码仓库，数据集与基准将公开发布

一句话总结

多参考图像生成模型在输入超过 3 张参考图时性能急剧退化，根本原因是缺乏结构化长上下文训练数据。本文构建了 MacroData（40 万样本，最多 10 张参考图，覆盖 4 个互补维度）和 MacroBench（4000 样本标准化评测），训练后开源模型性能大幅逼近闭源水平。

研究背景与动机

In-context generation 已成为图像合成的主流范式，使模型能够直接基于交错的文本和视觉参考生成图像。单参考和少参考任务（身份保持生成、风格迁移）已取得显著进展，但许多真实场景——多主体组合、叙事插画、新视角合成——天然需要对大量参考图像进行推理。这种多参考设置本质上更具挑战性，且在很大程度上未被解决。

即便是最强的开源模型也在这一场景下挣扎。OmniGen2 被限制为最多 5 张输入图像；Bagel 虽理论上设计为接受无限输入，但在超过 3 张参考图时表现出严重的性能退化。论文将这一缺陷的根因归结为一个关键的数据稀缺：与单参考生成不同（主要涉及从单一来源提取和复现特征），多参考生成要求模型理解密集的参考间依赖——时序动态、空间一致性、跨输入的身份保持——并将它们无缝整合为连贯输出。现有数据集以单参考或少参考对为主，缺乏学习这些依赖所需的结构化长上下文监督。

同时，缺乏标准化评估协议也阻碍了进展。现有基准如 OmniContext 仅限于最多 3 张输入图的定制任务，更广泛的设置未被评估覆盖。这一双重缺口——训练数据和评估工具——构成了本文的动机。

预备知识

理解本文需要把握两个核心概念。第一是 in-context image generation：模型在上下文中接收参考图像和文本指令，直接生成目标图像，无需额外的编码器或适配器微调。第二是 多参考间依赖（inter-reference dependencies）：当参考图数量增加时，模型不仅需要理解每张图的内容，还需捕捉图像之间的关系——空间布局、时序连续性、风格一致性、身份对应。

本文的基线模型包括 Bagel（基于 Transformer 的统一视觉-语言模型，支持任意数量输入图像）和 OmniGen2（限制最多 5 张输入图像的 in-context 生成模型）。二者均采用 next-token prediction 范式，将图像 token 化后与文本 token 在统一序列中处理。

Customization 子集（Fig. 3）：将多个参考物组合到连贯的原创场景中。元数据来源包括 OpenSubject（200 万人脸身份）、MVImgNet（20 万物体视频，238 个类别）、DL3DV（1 万场景视频）、Vibrant Clothes Rental（5 万服装图）、WikiArt（1 万艺术作品）。采样流程为：按 8:6:3:2:1 比例混合人物/物体/场景/服装/风格 → LLM 评估组合合理性并迭代重采样 → Nano Banana Pro 生成目标图像 → VLM 双向一致性评估过滤不合格样本。

Illustration 子集（Fig. 4）：从 OmniCorpus-CC-210M 的交错图文序列中，利用 VLM 识别与前文图像和文本高度语义相关的"锚点图像"作为生成目标，前序上下文作为输入条件。由于原始文本嘈杂冗长，采用强 VLM 重新组织每个序列——重评语义相关性、丢弃与叙事流不一致的图像、合成简洁的文本上下文。

Spatial 子集（Fig. 5）分为两类。Outside-in 物体：从 Objaverse 的规范视角中采样输入和目标视图，通过空间重叠过滤确保物理合理性；定义 10 个规范视角（上/下/左/右/前/后 + 四个对角），水平序列按顺时针排列。Inside-out 场景：从全景图像（DIT360, Pano360, Polyhaven）出发，用 VLM 分类为室内/室外，水平序列按逆时针排列。两种设置均严格确保输入视角与目标之间的视觉重叠。

Temporal 子集（Fig. 6）：从 OmniCorpus-YT 视频中，用 TransNetv2 进行镜头边界检测并提取中心关键帧。利用 DINOv2 视觉特征相似度将关键帧分组为连贯序列（确保场景内视觉连续性）。VLM 为每个序列生成描述性摘要并评分，过滤低分样本。每个有效序列的最后一帧作为生成目标。

MacroBench：标准化评测基准

MacroBench 沿两个维度结构化：任务维度（4 种任务）× 输入维度（1-3 / 4-5 / 6-7 / 8-10 张图像），总计 4000 个评测样本，每个任务×图像数组合 250 个。所有评测数据严格与训练集隔离。

评测采用 LLM-as-Judge 范式。经系统比较，选择 Gemini-3-Flash 作为评判模型（而非 GPT-4.1，后者在处理多参考图时评估质量退化，尤其在需要 3D 推理的 Spatial 任务上）。人类一致性验证显示 Gemini-3-Flash 的 Pearson 相关系数达 $r = 0.821$（Table 6），远优于 GPT-4.1 的 $r = 0.555$。

评分体系设计了任务特异的度量指标对：

任务指标 1指标 2聚合公式
CustomizationICS (图像一致性)PFS (指令跟随)$S = \sqrt{\text{ICS} \times \text{PFS}}$
IllustrationTCS (文本一致性)ICS (图像一致性)$S = \sqrt{\text{TCS} \times \text{ICS}}$
SpatialVTS (视角变换)CCS (内容一致性)$S = \sqrt{\text{VTS} \times \text{CCS}}$
TemporalCCS (内容一致性)ISCS (序列一致性)$S = \sqrt{\text{CCS} \times \text{ISCS}}$

选择几何均值而非算术均值有明确理由：几何均值对任一维度的严重失败惩罚更强——如果一个指标趋近于零，总分也趋近于零，无论另一指标多高。对于 Customization 的 ICS，由于需要忠实再现每一张参考主体，首先计算每张参考图的 ICS，然后通过调和均值聚合：

$$\text{ICS} = \frac{n}{\displaystyle\sum_{i=1}^{n} \frac{1}{\text{ICS}_i}}$$

调和均值确保对任意单一参考的低保真度会显著压制整体 ICS。最终 MacroBench 总分为四个任务分数的算术均值。

跨任务协同效应

Table 3 的消融实验揭示了一个重要发现：全量数据联合训练（+ All）的整体性能优于任何单任务子集训练，体现了跨任务协同效应（cross-task synergy）。具体而言：

Bagel + All 在全部 8 个指标上的平均分为 5.71，而最强单任务子集 Bagel + Customization 仅为 4.27。四个子集分别在各自任务上取得最优单项表现（如 Illustration 子集在 Illustration 1-5 上达 5.93），但跨任务迁移效果有限。

论文将这一现象解释为：不同任务训练了模型的互补能力——Customization 训练身份保持，Spatial 训练几何推理，Temporal 训练时序连贯性，Illustration 训练叙事理解。这些能力的组合使模型在每个任务上都获得额外增益。

数据比例与缩放分析

论文研究了不同输入图像数量的训练样本分布如何影响性能（Fig. 8）。对于渐进式任务（如 Customization，难度随输入数量递增），上采样大输入样本（如 1:3:7:9 比例）可大幅提升高输入性能而不损害低输入性能。对于非渐进式任务（如 Temporal），不同比例的影响微乎其微。基于此发现，MacroData 对 Customization 采用 2:2:3:3 比例，其余任务采用 1:1:1:1。

数据缩放实验（Fig. 9）考察了 1K/5K/10K/20K 样本对 Customization 性能的影响。结论是：1K 到 10K 之间增益最陡峭，10K 到 20K 边际递减但仍有正收益。基于此将每个任务缩放至 100K 样本。在 Text-to-Image 数据混合比例上，10% 的 T2I 数据即可维持模型的文本到图像生成能力（GenEval 分数几乎无损），超过 10% 的边际收益可忽略。

Token Selection 策略探索

添加更多输入图像线性扩展 token 序列，引入类似 LLM 的长上下文低效问题。论文评估了三种 token selection 策略（Fig. 11）：

Block-wise Selection：基于 query-key 注意力分数的块均值保留 top-K token 块。90% 保留率时平均分 8.21，略优于基线 8.02——表明少量冗余 token 的移除反而有助于聚焦。

Image-wise Selection：通过注意力分数在每个 token 的扩散过程中选择 top-K 图像。表现不佳（最优仅 7.67），表明粗粒度的图像级过滤会造成信息丢失。

Text-aligned Selection：在 prefilling 阶段通过文本-图像和图像-图像注意力分数选择每张图像的 top-K token。50% 保留率达 8.13，接近全量基线。进一步分析揭示了有趣的 VAE/ViT 互补性：

$$\text{Performance} \approx \alpha \cdot f(\text{VAE tokens}) + (1-\alpha) \cdot g(\text{ViT tokens})$$

其中 $\alpha$ 随输入图像数量变化——少图时保留 VAE token 更关键（捕捉低层视觉细节），多图时保留 ViT token 更重要（捕捉高层语义信息以进行跨图推理）。

Think & Collage 策略

论文还验证了两种直觉上可能有效但实际表现不佳的策略。"Think-before-generation"（Table 5）让模型在生成图像前先输出推理文本。结果：反而劣于无思考的基线。论文假设：没有针对多参考推理的显式训练，模型固有地难以跨多张图像综合信息，推理文本反而引入噪声。

"Collage as Proxy"将多张参考图拼接为单张空间网格作为代理输入。结果同样劣于基线（Bagel + Ours 从 8.02 降至 5.60）。原因在于分辨率损失：将多张图压缩到单张拼贴中限制了每个组件图像的分辨率，模型无法从降质的输入中提取足够的细节信息。

讨论

MacroData 的设计体现了一个方法论洞察：多参考生成的瓶颈不在模型架构，而在训练数据的结构。当 Bagel 和 OmniGen2 这些模型的架构理论上支持多图输入时，它们的性能退化纯粹是因为训练集中缺乏对应的监督信号。这与 NLP 中的"数据为王"原则一致，但本文进一步表明：数据的结构化组织（四维覆盖、渐进式比例分配）比简单的数据量增加更为关键。

跨任务协同效应的发现对数据集设计有普遍启示。传统做法是为每个下游任务收集专门数据，但本文表明异质任务的联合训练可以通过能力互补产生超加性收益。这暗示未来的图像生成数据集应追求能力维度的正交覆盖，而非单一任务的深度饱和。

Token selection 的实验为长上下文图像生成的效率优化指明了方向。Text-aligned selection 在 50% 保留率下接近全量性能，意味着理论上可以将多参考生成的计算成本减半而几乎不损失质量。VAE/ViT 互补性发现则暗示自适应策略（根据输入规模动态调整保留比例）可能进一步提升效率-质量前沿。

局限分析

闭源模型依赖（作者隐含承认）。MacroData 的 Customization 子集依赖 Nano Banana Pro 生成目标图像，所有子集使用 Gemini 系列进行质量评估和过滤。这引入了两个问题：其一，训练数据的质量上限受制于闭源模型的生成能力——学生不可能超越教师的上限（尽管跨任务协同可能部分突破这一限制）；其二，整个数据管线的可复现性取决于这些闭源 API 的持续可用性和一致性。

10 张参考图的上限约束。论文将最大输入限制为 10 张参考图像，但真实应用场景（如完整视频续写、大规模场景重建、多角色故事绘本）可能需要远超 10 张的参考输入。当前设计是否以及如何泛化到 20、50 或更多参考图尚不明确。考虑到 token 序列长度随参考图数量线性增长，计算瓶颈将在更大规模下变得更加尖锐。

Spatial 子集的规范化约束。Outside-in 和 inside-out 设置均限于预定义的规范视角（10 个标准方向）。真实的新视角合成需求往往涉及任意连续视角，且物体/场景的复杂度远超 Objaverse 和全景图的分布。从规范视角到任意视角的泛化能力未被评估。

评估偏差的残余风险。尽管 Gemini-3-Flash 与人类评分的 Pearson 相关达 0.821，这意味着仍有约 33% 的方差未被解释。特别是论文承认 GPT-4.1 在 Spatial 任务（需要 3D 推理）上评估质量退化——那么 Gemini-3-Flash 在这些任务上的可靠性是否同样可能存在盲区？人类验证研究仅包含 280 个样本（总基准的 7%），统计功效有限。

多参考图像生成的真正瓶颈不在模型架构，而在训练数据的结构化程度——给模型看到正确的多图关系，它自然就能学会推理。
