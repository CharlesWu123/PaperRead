核心摘要

做什么：把 Agent 轨迹的「验证」本身当成一条可扩展的算力轴，做成免训练、跨领域通用的轨迹奖励模型（TRM）。
怎么做：不取 argmax 分数 token，而是对打分 token 的 logprob 分布取期望，再沿三条轴放大——打分粒度 $G$、重复评估次数 $K$、评价维度数 $C$；选最优轨迹用 $\mathcal{O}(Nk)$ 的 Probabilistic Pivot Tournament。
效果：Terminal-Bench V2 86.5%、SWE-Bench Verified 78.2%、RoboRewardBench 87.4%、MedAgentBench 73.3%，全部 SOTA，零微调。
适用：best-of-N 选轨迹、Agent 任务进度监控、RL 稠密奖励。
前提：验证器需要能拿到 top-logprobs。

关键创新

1. 连续奖励：对分数分布取期望，而不是取 argmax。标准 LM Judge 让模型吐一个离散分数并取最高概率 token，把整个信念分布压成一个整数，导致在 Terminal-Bench 上有 27% 的打分打平——两条明显优劣不同的轨迹拿到同一个分。本文改为

$$R(x,\tau)=\frac{1}{CK}\sum_{c=1}^{C}\sum_{k=1}^{K}\sum_{g=1}^{G} p_\theta(v_g \mid x,c,\tau)\,\phi(v_g)$$

其中 $\phi(v_g)$ 把第 $g$ 个分数 token 映射为标量。信息量没变，但解码空间从「整数格点」变成了连续实数，原本被四舍五入到同一格的两个信念被分开了。论文的对照实验（同一批 100 对轨迹）非常干脆：

方法奖励定义判对打平判错
Judge（离散，$G{=}5$）$\phi(\arg\max_g p_\theta(v_g))$12880
Verifier（连续，$G{=}5$）$\sum_{g=1}^{5}p_\theta(v_g)\phi(v_g)$69031
Verifier（连续，$G{=}20$）$\sum_{g=1}^{20}p_\theta(v_g)\phi(v_g)$77023

注意第一行：离散 Judge 判错 0 次，看起来「从不犯错」，但 88% 的样本它根本没给出可用信号。把打平消掉之后，准确率才是可比的。

2. 三条正交的验证 Scaling 轴。$G$（粒度）提升分数分离度，$K$（重复）平均掉单次采样偏置，$C$（维度分解）覆盖轨迹质量的互补侧面。Terminal-Bench 2.0 上单独拉每一条都单调涨：$G$ 从 1 到 20 是 73.1%→77.5%，$K$ 从 1 到 16 是 74.7%→77.4%，单一维度 75.2–76.4% 而三维度集成到 78.3%。这三个旋钮都能按延迟预算独立调，是本文最实用的部分。

3. 粒度为什么有效：信噪比解释。作者把正确/错误轨迹的分差 $\Delta=s_c-s_i$ 拆成信号和噪声：

$$\mathrm{SNR}(G)=\frac{\mathbb{E}[s_c-s_i]}{\sqrt{\mathrm{Var}(s_c-s_i)}}$$

成对验证准确率是 $\mathrm{SNR}(G)$ 的单调函数——样本量固定时，标准化后的分差越大，$s_c>s_i$ 的概率就越高。这一步把「调大 $G$ 有用」从经验观察变成了可解释的机制。

4. 手写的三个评价维度（以 Terminal-Bench 为例）。不是泛泛的「好不好」，而是三个正交且都以终端输出为准的检查项：Specification Adherence（路径/格式/约束这些具体要求有没有真的满足，而不是解了一个相似但不同的问题）、Output Match（最后那条验证命令的 stdout 是否逐字符匹配预期）、Error Signal Detection（轨迹尾部有没有未修复的 traceback、非零退出码、编译失败）。仓库里明确写了一条硬规则：只信终端输出，不信 Agent 的自我陈述。

5. Probabilistic Pivot Tournament：把 best-of-N 从 $\mathcal{O}(N^2)$ 压到 $\mathcal{O}(Nk)$。三步：(a) Ring pass——采一个随机 Hamiltonian 环，只打 $N$ 条相邻有向边，每个候选恰好一次出现在 prompt 的 A 位、一次在 B 位，位置偏置在环上期望抵消；(b) 环上平均胜率 top-$k$ 成为 pivot 集 $\mathcal{P}$；(c) 其余候选只和 $\mathcal{P}$ 比。总比较数 $N+k(N-k)+\binom{k}{2}$。每次比较通过 Bradley–Terry 转成软胜场 $p(a\succ b)=\sigma(R_a-R_b)$。

机器人那一行最有说服力：RoboReward-8B 用约 45k episodes 训练、Robometer-4B 用约 100 万条比较训练，而本文零样本、不做任何微调，直接高出 6 个点；同 VLM 的离散 Judge 只有 70.8%。同时在人工标注对齐上，连续奖励 + $K{=}8$ 把 MAE 从 1.11 降到 0.72。

自验证也成立。Terminal-Bench 2.1 上用 deepseek-v4-flash 同时做生成和验证：best-of-3 从 79.4% 到 86.5%±1.1%，best-of-5 从 78.7% 到 88.0%±0.6%。模型评判自己产出的轨迹仍有显著增益。

顺带的三个副产品

  • 进度估计：验证器分数与步骤时间顺序强相关（Fig. 8），可以当任务完成度曲线用；作者给 Claude Code 和 Codex 都做了扩展。
  • RL 稠密奖励：$r_i=r_{\mathrm{correct},i}+r_{\mathrm{format},i}+\beta\,r_{\mathrm{reasoning},i}$，提升 SAC（机器人）和 GRPO（数学）的样本效率。
  • 闭源模型兼容：不给 logprob 的前沿模型可以走两阶段方案——闭源模型出推理，开源可见 logits 的模型出分数（Appendix B.6）。

两个要点提醒

作者自述的局限：依赖 scoring-token logits，排除了一批只提供受限 API 的前沿模型；三条 Scaling 轴不穷尽，criteria 目前是手写的，未来应当可学习或按领域动态生成；RL 实验只做了单轮，多轮长时序信用分配尚未验证。

我的判断：评价维度是按 benchmark 手写的 markdown（criteria/terminal_bench.md 等），这意味着「免训练」的代价是「需要人工写好 rubric」——换到一个新领域，性能上限相当程度取决于谁来写这三段提示词，这部分成本在论文里没被计入。另外 Ring pass 只用 $N$ 条边估计初始强度，$k$ 很小时 pivot 选错会直接把真正的最优候选排除在精细比较之外；论文报告了整体增益，但没有单独报 PPT 相对全 $\mathcal{O}(N^2)$ round-robin 的选择损失。

生成早就在 scaling，验证还停留在四舍五入取整。
这篇论文做的事，是把那个被丢掉的小数位捡回来。
