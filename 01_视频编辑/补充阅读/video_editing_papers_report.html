核心结论

这 3 篇论文刚好构成一条清晰路线：Wan 提供强大的开放视频基础模型和统一编辑框架底座；OpenVE-3M 解决指令式视频编辑最缺的数据与评测问题；Bernini 则把 MLLM 的语义推理显式放到扩散视频生成之前，让“理解编辑意图”和“渲染视频像素”分工更清楚。

如果只看视频编辑方向，最重要的趋势不是单纯把 DiT 做大，而是把编辑任务拆成三层：高质量编辑数据、语义级计划、像素/时序级保真。OpenVE-3M 补数据，Bernini 补语义规划，Wan/VACE 补大模型底座和多模态条件统一。

二、三篇论文放在一起看：视频编辑范式的迁移

传统视频编辑模型常把问题看成“输入视频 + 文本指令 -> 输出视频”的端到端映射。这个形式简洁，但难点被压进一个黑盒里：模型既要理解“把蓝色 SUV 换成红色 SUV”这种局部语义，又要知道哪些像素不能动，还要维持跨帧身份、运动、材质、光照和背景稳定。一旦数据质量不够，或者指令与视频内容之间存在长程关系，模型很容易出现三类错误：编辑错对象、编辑对了但破坏未编辑区域、视频质量/时序稳定性下降。

这 3 篇论文代表了三个不同层面的回答。Wan 的回答是：先做一个强视频基础模型，然后用统一条件单元把编辑、参考、mask、控制信号接进去。OpenVE-3M 的回答是：没有高质量、多类别、长指令的视频编辑数据，模型架构再漂亮也会训练不稳、泛化不足。Bernini 的回答更进一步：不要让扩散模型独自承担“理解意图”这件事，而是让 MLLM 先做语义规划，再让 DiT 专注渲染。

三、Wan：用统一条件单元扩展视频基础模型

Wan 的主报告不是一篇单纯的视频编辑论文，而是一篇开放视频基础模型报告。它的核心模型采用 Diffusion Transformer 与 Flow Matching 路线，并强调大规模数据、spatio-temporal VAE、训练/推理加速和自动评测。对视频编辑最相关的是第 5.2 节 Unified Video Editing，其思想继承自 VACE：把不同形式的编辑条件统一成同一个输入范式。

论文将 Video Condition Unit 写成：

$$V = [T; F; M]$$

其中 $T$ 是文本提示，$F=\{u_1,u_2,...,u_n\}$ 是上下文视频帧序列，$M=\{m_1,m_2,...,m_n\}$ 是 mask 序列。$F$ 与 $M$ 在空间尺寸 $h\times w$ 与时间长度 $n$ 上对齐。这个公式背后的人话解释是：视频编辑不应该只靠一句文字，而要把“要改什么”“保留什么”“参考什么”“哪些区域可动”都变成模型能统一读取的条件。

更关键的是概念解耦策略。论文将上下文帧按 mask 切成待修改区域和待保留区域：

$$F_c = F \times M, \quad F_k = F \times (1-M)$$

$F_c$ 表示 reactive frames，即需要响应编辑的区域；$F_k$ 表示 inactive frames，即应该保留的区域。这个设计直接针对视频编辑最核心的矛盾：既要改变局部，又不能污染全局。比起只把源视频 latent 拼进去，显式区分可编辑区域和保留区域能让任务边界更清楚，也更利于多任务收敛。

Wan/VACE 的另一个重点是训练方式。论文给出两种路线：一种是带 VCU 对整个 Wan 模型做 fully fine-tuning；另一种是 Context Adapter Tuning，用类似 Res-Tuning 的可插拔 Context Adapter 将上下文 token 重新注入原 DiT block，从而不改基础模型权重。这两个路线的取舍很实际：全量微调上限更高，但成本大；adapter 方式更利于复用基础模型，但总体模型规模和条件路径会更复杂。

实验呈现上，Wan 在视频编辑章节主要给定性结果，包括 Fig. 21 的统一可控生成与编辑框架、Fig. 22/23 的多任务编辑可视化、Fig. 24 的 advanced video/image editing。它展示了 inpainting、extension、outpainting、depth、pose、gray、scribble、layout、object、face 等任务可以放在同一个框架下。这说明 Wan 的视频编辑贡献更像“基础设施型能力”：它不一定在这一节给出大量编辑 benchmark 数字，但提供了把不同编辑任务统一到大视频模型上的工程路径。

局限方面，Wan 作者明确指出三点：第一，大运动下细粒度细节保持仍然困难；第二，14B 模型推理成本高，未经额外优化在单张高端 GPU 上约需 30 分钟；第三，作为通用基础模型，在教育、医疗等垂直场景仍缺少领域专长。对视频编辑而言，第一点尤其关键，因为编辑任务常常要求“局部变化 + 大运动 + 身份保持”同时成立，这是当前扩散视频模型最容易失控的组合。

四、OpenVE-3M：视频编辑最缺的不是模型，而是好数据

OpenVE-3M 的出发点非常直接：图像编辑已经受益于高质量 instruction-based image editing 数据集，但 instruction-guided video editing 数据仍然稀缺。论文指出已有 IVE 数据集的四个问题：规模小、编辑类别有限、指令过短、编辑质量差。比如 InsViE-1M 和 Señorita-2M 虽然有 1M/2M 规模，但平均指令长度只有约 4.4 和 3.6 个词，难以表达精确编辑意图。

OpenVE-3M 构建了 3M 视频编辑样本，分为两大类：Spatially-Aligned 与 Non-Spatially-Aligned。前者要求编辑后视频与原视频在运动和时空结构上强对齐，包括 Global Style、Background Change、Local Change、Local Remove、Local Add、Subtitles Edit；后者允许运动发生创造性变化，但要保持主体一致，包括 Camera Multi-Shot Edit 与 Creative Edit。

类别编辑含义关键难点
Global Style整体风格、时间、天气变化保持原始运动和细节不漂移
Background Change替换背景场景前景 mask 稳定、背景与主体融合
Local Change对象变换、颜色/材质/年龄变化定位正确对象，不误改周围区域
Local Remove/Add删除或添加局部对象遮挡补全、跨帧一致、插入物运动合理
Subtitles Edit添加、删除、修改字幕文字渲染与位置稳定
Camera Multi-Shot / Creative Edit镜头变化或动作创意变化非严格对齐下的主体一致性与指令遵循

数据生成流程分三阶段。第一阶段是预处理：从 Open-Sora-Plan、OpenViD-HD、UltraVideo 中建立 1M 基础视频库，抽取 65 到 129 帧、720P 分辨率片段；用 Qwen2.5-VL-72B 生成长描述和可检测对象名；用 Video DepthAnything、OpenCV Canny、Grounded SAM2、DAM 生成深度、边缘、检测、分割、局部对象描述。第二阶段是 taxonomy-guided 生成：不同编辑类别用不同工具链，例如 FLUX-Kontext-dev 做首帧图像编辑，Wan2.1-Fun-Control 或 Wan2.2-I2V 生成视频；Creative Edit 和多镜头编辑使用 Seedance 的 I2V/Native Multi-Shot 能力。第三阶段是过滤：用 Instruction Compliance、Consistency & Detail Fidelity、Visual Quality & Stability 三个 1-5 分维度筛选，并强调 Instruction Compliance 是另外两项的上界。

OpenVE-Edit 模型由 MLLM、MoE-Connector 和 DiT 三部分组成。输入视频和编辑指令先送入 MLLM，得到更高层的语义和时空关系表示；MoE-Connector 按任务类型选择专家处理这些隐藏特征；最后与 umT5 文本特征拼接，作为 DiT 的 cross-attention 条件。同时，原视频经 VAE 得到 latent，与噪声沿 channel 维拼接，帮助模型保留源视频细节。

MoE-Connector 的核心公式为：

$$Y=W_o\left(\mathrm{MoE\text{-}Dec}\left(Q_l,\mathrm{MoE\text{-}Enc}(F_i(X_{in}))\right)\right)$$

其中 $X_{in}$ 是 MLLM hidden states，$Q_l$ 是可学习 query，$F_i$ 做维度映射，MoE encoder/decoder 负责从不同编辑任务中抽取关键表示。专家 FFN 写成：

$$y=\sum_{i\in S} w_i\cdot\left(W_{i,2}\cdot \mathrm{GELU}(W_{i,1}x+b_{i,1})+b_{i,2}\right)$$

其中 $S=\mathrm{topk}(\mathrm{softmax}(W_gx),k)$。人话解释是：不同编辑任务不必共用同一套中间变换，模型可以按输入内容激活少量专家，让“字幕编辑”“局部替换”“背景变化”拥有更专门的处理路径。

论文还借鉴 ControlNet，将 connector 最后一层 $W_o$ 零初始化，使它在训练初期近似不可见，避免随机初始化特征干扰原有 umT5 条件。这是一个很实用的训练稳定性设计：新模块不是一上来就强行改变生成路径，而是先保持基座模型行为，再逐步学习编辑增量。

OpenVE-Bench 包含 431 个 video-edit pair，覆盖 8 类任务，并用 MLLM 打分。根据论文表 2/3，OpenVE-Edit 在开源模型中取得较高总体表现：Seed1.6-VL 评测 Overall 为 2.41，Gemini 2.5 Pro 评测 Overall 为 2.49，超过 VACE、OmniVideo、InsViE、Lucy-Edit、ICVE、DITTO 等开源模型。不过闭源 Runway Aleph 仍明显更强，Gemini 评测 Overall 为 3.65，在 Local Change、Local Remove、Camera Edit 等项优势尤其明显。

这组结果说明两件事。第一，OpenVE-3M 确实提升了开源模型在多类别指令编辑上的覆盖度，尤其是字幕编辑、背景变化、局部变化等任务。第二，当前开源视频编辑离强闭源系统仍有距离，特别是在复杂局部操作和非空间对齐编辑上，分数仍偏低。例如 Camera Edit 中 OpenVE-Edit 在 Seed1.6-VL 表为 1.24，Gemini 表为 2.02，说明多镜头/相机编辑仍然是难点。

五、Bernini：让 MLLM 做语义规划，让 DiT 做渲染

Bernini 的核心洞察是：MLLM 与 diffusion model 不该只是简单串联，而应该有清楚分工。MLLM 擅长理解长指令、多参考图、多视频上下文和复杂关系；DiT 擅长在 VAE latent space 中生成高保真图像/视频。于是 Bernini 让 MLLM-based planner 先预测目标视频的语义表示，再由 DiT-based renderer 根据这个语义计划渲染最终像素。

论文选择的语义接口不是文本 token，也不是 CLIP embedding，而是 MLLM 自身的 ViT embedding space。原因是 MLLM 已经在这个空间里表示视觉内容，让它预测目标 ViT embedding 能更自然地继承预训练理解能力。训练时，planner 采用 masked generative modeling 思路，用轻量 ViT embedding decoder 从 MLLM hidden states 恢复被 mask 的目标 ViT tokens；推理时，从 fully masked target tokens 逐步填充完整目标表示。

Renderer 是 DiT，通过 flow matching 在 VAE latent token 上去噪。对于编辑任务，renderer 的条件包括 planner 产生的 semantic embedding、文本特征，以及 source VAE features。可以把它理解成两条信息流：semantic embedding 告诉模型“应该变成什么”，source VAE features 告诉模型“哪些细节和结构要保留”。

Bernini 的 Figure 3 把框架分为五部分：统一多模态序列、MLLM semantic planner、DiT renderer、segment-wise hybrid attention mask、Segment-Aware 3D RoPE。SA-3D RoPE 是为多视觉输入设计的。普通 3D RoPE 只编码时间、高度、宽度，当多个 source image/source video/target placeholder 被拼成一个序列时，不同 segment 可能共享相同的时空坐标，造成身份和来源混淆。SA-3D RoPE 给不同 segment 加相位调制，让同样的 $(t,h,w)$ 在不同输入段中可区分。

Bernini 还引入 latent-space Chain-of-Thought，让 planner 在输出最终 embedding 前先进行推理。这个设计对视频编辑很重要，因为很多编辑指令不是直接视觉变换，而是带因果或时间推理。例如“after a week”“overcooked”这类提示需要模型先推断目标状态，再生成视觉结果。传统 renderer-only 模型往往只能做表层风格或对象替换，遇到隐含语义变化会更容易失败。

Bernini 组件职责对视频编辑的意义
MLLM Planner读取文本、图像、视频、target placeholder，预测目标 ViT semantic embeddings把复杂编辑意图转成紧凑语义计划
DiT Renderer在 VAE latent space 中用 flow matching 生成视频负责高保真像素、时序运动与视觉质量

SA-3D RoPE区分多视觉输入 segment 的时空位置降低参考图/源视频/目标 token 混淆
Latent CoT在语义空间进行推理后再规划增强因果、时间、复杂指令编辑能力

实验上，论文首页给出 open-ended video editing human preference leaderboard：HappyHorse-1.0 BT score 1080，Bernini 1044，Wan2.7 1034，Grok-imagine-video 964，Kling_v3_omni 878。Bernini 在平均对手下 win rate 为 56.3%，略高于 Wan2.7 的 54.9%。这说明在开放式编辑偏好中，Bernini 已达到强商业/闭源系统附近的竞争力。

论文还在 OpenVE-Bench、OpenS2V-Eval、Bernini-Bench 上报告 SOTA 表现，并包含 video editing、reasoning-augmented video editing、video generation、ablation、generalization 等实验。结合公开 README，Bernini 的模型族分为 full Bernini 与 Bernini-R：full Bernini 是 MLLM semantic planner + DiT renderer；Bernini-R 是 renderer-only，基于 Wan diffusion renderer 微调。README 明确说 full Bernini 在复杂指令分解与语义规划上更强，而 Bernini-R 更简单、渲染一致性强，但少了完整 planner。

Bernini 的局限也比较清楚。第一，它的系统复杂度和推理成本高：full pipeline 依赖 Qwen2.5-VL planner、Wan2.2 renderer、VAE、T5 text encoder、并行推理配置，README 参考环境甚至是 H100/CUDA 12.4/PyTorch 2.5.1。第二，semantic planning 能提升复杂编辑，但最终视觉质量仍受 renderer 与训练数据限制。第三，它依赖强 MLLM 的预训练理解能力，若指令、参考图、视频上下文超出 planner 能力范围，后续 DiT 也很难补救。

七、对视频编辑研究和落地的判断

第一，视频编辑正在从“单模型端到端编辑”转向“理解、计划、渲染、保真”的分层系统。Wan 的 VCU、OpenVE-Edit 的 MLLM + MoE-Connector、Bernini 的 MLLM planner 都在做同一件事：不要把文本指令直接扔给 DiT，而是先把指令与视频内容对齐成更结构化的条件。

第二，数据质量会继续决定开源模型上限。OpenVE-3M 的贡献不只是 3M 规模，而是它把编辑任务拆成了可操作的 taxonomy，并用 MLLM 评分把 instruction compliance 放在最高优先级。这一点很关键，因为视频编辑里“画质好但没按指令改”其实是失败样本，不应该被视觉质量掩盖。

第三，复杂编辑会越来越依赖 MLLM。简单风格迁移、字幕删除、局部换色可以靠 renderer-only 或控制模型解决，但涉及时间推理、因果变化、多参考组合、对象身份迁移时，纯扩散模型很难可靠理解目标状态。Bernini 的 ViT embedding semantic bridge 是一个很有代表性的方向：让 MLLM 输出视觉语义计划，而不是只输出文本描述。

第四，评价体系还没有完全稳定。OpenVE-Bench 用 MLLM 评分并与人类判断对齐，Bernini 使用人类偏好 leaderboard 和自建 Bernini-Bench，但不同 benchmark 的任务分布、分辨率、模型版本和评委模型都会影响结论。实际选型时，不宜只看 Overall 分数，应按业务任务拆开看：局部替换、背景变化、字幕编辑、镜头变化、参考图编辑、复杂推理编辑，对模型能力要求不同。

第五，工程落地要警惕成本。Wan 14B 未优化推理约 30 分钟，Bernini full pipeline 参考 H100 多卡环境，OpenVE-Edit 虽是 5B 但仍依赖 1280x704 视频编辑和 MLLM 特征。短期落地更现实的路线可能是：用小模型或 renderer-only 处理简单批量编辑，用 full planner 模型处理高价值复杂编辑，再用自动评测/人工审核筛掉失败样本。

八、局限与风险

三篇论文共同暴露出几个领域级局限。第一，大运动下的细节保持仍然是硬问题。Wan 明确承认大运动场景中 fine-grained details preservation 仍困难；OpenVE 的 Local Remove、Camera Edit 分数不高也侧面说明，强时序变化和局部结构重建仍不稳定。第二，自动评测依赖 MLLM，虽然更接近人类偏好，但会引入评委模型偏差。OpenVE 为了过滤数据比较了 Qwen3-VL、InternVL、Seed1.6-VL、Gemini2.5-Pro，不同模型准确率并不一致。第三，多数系统仍依赖合成数据、商业 API 或大规模内部数据，论文可复现性与真实训练成本之间有差距。

另一个更隐蔽的问题是“编辑边界”的定义。对于 Spatially-Aligned 编辑，保留原运动和细节是硬要求；对于 Creative Edit 或 Camera Multi-Shot Edit，目标本来就允许新运动出现。一个统一模型如果没有清楚区分任务边界，就可能在该保守时过度生成，在该创造时又过度保留。OpenVE 用 taxonomy 和 MoE 专家缓解这个问题，Wan 用 mask 概念解耦缓解，Bernini 用 planner 语义推理缓解，但都还不是最终答案。

九、建议阅读顺序

如果目标是快速理解视频编辑技术演进，建议先读 OpenVE-3M，因为它把任务类别、数据构造和评测维度讲得最直接；再读 Wan 的第 5.2 节和第 6 节，理解基础模型如何承载统一编辑；最后读 Bernini，重点看 Introduction、Figure 3、Methods 和 Experiments，理解为什么下一阶段会从“条件注入”走向“语义规划”。

如果目标是工程选型，优先看代码状态：Wan2.1 是成熟开放底座，生态更广；OpenVE-3M 适合拿 benchmark 和数据定义做训练/评测参考；Bernini 更适合研究复杂编辑和多模态语义规划，但部署成本更高。

视频编辑的下一步，不是让一个模型盲目学会所有变化，而是让系统先理解该变什么、该保留什么，再把变化稳定地渲染出来。
