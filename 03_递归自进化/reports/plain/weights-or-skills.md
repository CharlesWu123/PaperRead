# 通俗版 · Weights or Skills：能力应该长在权重里，还是写成代码

> 能力训进模型就改不动了；写成代码，agent 才能自己改自己。

## 一分钟版本

- 这篇综述把机器人学习切成两派，判据只有一句话：**最终交付的东西是什么**。一派交付一堆冻结的模型权重，另一派交付一段可读、可改、可 diff 的代码。
- 只有代码那一派能在**不做任何梯度更新**的情况下自我改进。这句话就是「冻结模型 + 只演化 skill」这条路线的合法性来源。
- 作者给「自改进」排了个四到五级的台阶，并给出三个机制（执行反馈 / 跨任务记忆 / 种群搜索）的**排他定义**——明确说清什么**不算**反馈、不算记忆、不算搜索。这套定义几乎可以原样搬到 LLM agent。
- 「skill」这个词被作者点名说「严重超载」，至少有五种互不相同的含义。五种含义里只有一种同时可读、可改、可拼装；而能上架卖钱的偏偏是另外两种。这个错配是全文最锋利的观察。
- 综述统计了 302 个系统，真正做到「反馈 + 记忆 + 搜索三合一」的只有 3 个，全部出现在 2026 年。作者说：这一格如此稀疏本身，才是本文要讲的结论。

## 两条路线的分野

想象两种做「会做家务的机器人」的方式。

**第一种：把能力训进权重。** 收集一百万条人类遥操作机器人的录像，训一个大模型，输入是摄像头画面加一句「把苹果放进碗里」，输出是关节该怎么动。这就是 VLA（视觉-语言-动作模型）那一派，代表是 RT-1、RT-2、OpenVLA、π0、GR00T。

对 LLM agent 工程师来说，这相当于：**收集海量轨迹数据，SFT 或 RL 一个模型，让能力沉淀在参数里**。

赌注是 scaling：数据够多、参数够大，能力自然涌现。优势是端到端、反应快、能靠 co-training 跨任务泛化。

失效模式作者写得很硬：「没有循环，也没有代码；靠插值而非搜索泛化，训练后无法被编辑、审计或重组。」典型故障叫**静默错误接地**——场景稍微偏离训练分布，模型不报错，只是默默做错。对应到 LLM agent，就是那种「模型自信地调错工具、传错参数，日志里看不出任何异常」的情况。综述里 11 个 VLA 系统，自改进能力一栏**全是空的**。

**第二种：让模型自己写代码。** 给 LLM 一套感知和控制的 API（`detect_object()`、`move_to()`、`grasp()`），让它当程序员，现场写一段 Python 把这些原语组合起来。这叫 code-as-policy，代表是 Code-as-Policies、Voyager。

对 LLM agent 工程师来说，这就是**你已经在做的事**：agent 自己写函数、自己定义工具、把它存进 skill 库。

优势很直接：不需要新的训练数据（在预训练模型上少样本提示就行）、能处理长任务（代码天生可组合）、可读可审计、执行前能人工过一眼、而且被约束在已审核的 API 内所以安全。

失效模式也很具体：**感知层认错东西时整段代码就崩**。而且可移植性只拿到「一半」的评价——理由是「API 级可移植，但被绑死在感知栈上」。这一条对 LLM agent 完全成立：你的 skill 能不能搬走，取决于它调的工具/API 表面稳不稳定，跟代码本身写得多漂亮没关系。

作者的立场不是「代码派更好」。原话的意思是：六个评价维度上，每个维度都至少有一个流派是弱的，**没有任何流派六项全优**。

还有一个结构性判断值得单独记：作者提出 skill 的三层栈——**Build（怎么造出来）、Distribute（市场和分发）、Adapt（装到本地后自己适应）**。宇树的 UniStore 已经能一键下载动作包了，但每个包都是**静态回放**，是能力最弱的那一档。市场宣传的价值（「按不同水果调整握力，别把它捏烂」）活在 Adapt 层，而**今天出货的 skill 里没有任何一个到得了这一层**。分发层已就绪、适配层空缺——这个诊断可以逐字搬到 LLM agent 的插件/MCP 生态。

## 「skill」这个词的五种用法

这是全文最有价值的一节。作者原话：「skill 一词被严重超载。」

五种含义，以及四个属性（能不能看懂 / 能不能改 / 能不能拼装 / 能不能分发）：

| 含义 | 机器人语境是什么 | LLM agent 里的对应物 | 可读 | 可改 | 可拼装 | 可分发 |
|---|---|---|---|---|---|---|
| latent policy（潜策略） | 用一个隐向量条件化的神经网络，代表 DIAYN/METRA | LoRA 微调进权重的行为、soft prompt 条件化 | 否 | 勉强 | 否 | 否 |
| option / primitive（原语） | 带先验的时序子策略，代表 SPiRL/OPAL | 固定的子流程、子 agent、预定义工作流节点 | 勉强 | 勉强 | 是 | 否 |
| code（代码） | 跑在某套 API 之上的可执行程序，代表 Voyager | agent 自己写的函数/脚本/工具定义 | 是 | 是 | 是 | 勉强 |
| robot app（打包行为） | 一键部署的动作包，代表 UniStore motion package | 装了就能用的插件、skill 包、MCP server 发行版 | 否 | 否 | 否 | 是 |
| market product（商品） | 上架、带版本、带定价的条目 | 付费 agent 商店条目、订阅制 skill | 否 | 否 | 勉强 | 是 |

看这张表最该记住两件事：

- **只有 code 这一种同时可读、可改、可拼装。**
- **只有 app 和 market product 天然可分发。**

这两句话摆在一起就是个错配：**能进化的那种 skill 不好卖，好卖的那种 skill 不会进化。** 整个 skill 市场要解决的就是这道裂缝。

最坑人的两种混用：

1. **把 latent policy 和 option 混着叫 skill。** 两者都是黑盒，但只有 option 能被上层规划器串起来。LLM agent 这边的翻版：有人管「微调出来的行为倾向」叫 skill，也管「注册好的子 agent」叫 skill，讨论时以为在说同一件事，其实一个根本不能被调度。
2. **把 code 和 robot app 混着叫「可交付的 skill」。** 两者都是「一个可以给你的东西」，但前者装到你这儿会继续变好，后者永远是同一段回放。这是 LLM agent 生态里最普遍的偷换：市场卖的是 app，宣传的是 code 的好处。

还有一句判据是全文的支点：**五种含义里只有 code 能在不做梯度更新的前提下自我改进。**

## 自改进程度的四个台阶

作者把这条谱系拆成一串顺序问句，每答一个「是」就升一级。起点在下面，往上四档。

**起点（第 0 档）：一次性生成代码。**（13 个系统，占了最大一块）
LLM 看一眼指令，写一段程序，扔出去执行，完事。代表是 Code-as-Policies、ProgPrompt、VoxPoser。
限制：**程序只写一次，从执行结果回到生成器没有任何通道，运行时失败就是失败。**
门槛：零。这也是为什么系统最多。
对号入座：只挂了一堆预定义工具、跑完就结束的 agent，全部停在这一档——工具再丰富也一样。

**第一档：失败了自己修。**（6 个系统）
执行过程里有信号回灌：成功检测器说没抓到、感知模块描述了当前场景、或者一段失败摘要。模型据此改代码重试。代表是 Inner Monologue、REFLECT、Code-as-Monitor。
门槛：**拿到执行接地的失败信号。** 注意不算的东西——人再下一句指令不算，模型自己拍脑袋写的批评不算。
作者的评语很精准：闭环是新意，**但这是一个短环——修正在任务结束时就被丢掉，什么也不积累。**
LLM agent 对应物：跑测试、看类型检查、读工具返回码，然后改代码重试。Reflexion 类的纯自我批评**不算**，因为没接地。

**第二档：成功的存下来复用。**（5 个系统）
验证过的代码写进一个跨任务的库，以后新任务先去库里检索。代表是 Voyager——它维护一个不断增长的已验证 skill 库，每个 skill 还带一条**「什么时候该用我」的守卫条件**。
门槛：**跨任务持久化 + 能检索 + 有验证守卫。** 三个缺一不可。特别注意作者的排他定义：**agent 自己无法扩展的固定 API 库不算记忆。** 上下文窗口不算，episode 内的 scratchpad 不算。
和上一档的关键差别是时间尺度：**能力跨任务复利，而不是每次从零重建。**

**第三档：种群搜索。**（3 个系统）
不再是「盯着一个方案反复修」，而是同时养着好几个候选程序，让它们真跑一遍拿分数，然后择优、变异。代表是 RoboEvolve、GEAR。
门槛：**候选之间必须被执行打分并互相比较。** 反复重采样但从不比较，不算搜索。
作者的定性：从「修复」转向「搜索」，探索变得显式且并行，**用算力换取跳出局部失败的机会**。

**第四档：三者合一的开放式循环。**（只有 3 个系统：ASPIRE、ENPIRE、RoboClaw，全是 2026 年，全是真机）
执行反馈 + 经验库 + 演化搜索在同一个闭环里，验证过的 skill 回流给未来任务。

为什么最高一档这么罕见？看这三个系统实际贡献的是什么就明白了：ENPIRE 的核心是**自动复位和并行 rollout**，RoboClaw 是**自复位的统一控制器**，ASPIRE 是**按原语粒度输出结构化 trace**。

全是工程基础设施，不是新算法。门槛是「让这个循环能无人值守地跑很多很多轮」。机器人做不到，因为每跑一轮就要有人把桌子上的杯子摆回原位。

作者明确表态：**这一格如此稀疏本身，而不是里面任何一个具体系统，才是这篇综述要作出的结构性观察。**

### 三个机制的排他定义（这段建议背下来）

- **反馈（Feedback）算**：任务内读到、并被用来改代码的执行接地信号——失败检测器、错误场景的感知或文本摘要、跑一遍程序得到的 verifier 或 reward。
  **不算**：新的人类指令；从不在运行时被查询的固定 value function；**没和执行接地的自然语言自我批评**。
- **记忆（Memory）算**：运行时写入的东西跨过任务边界存活下来，并被后续任务检索到——持久 skill 库，或可检索的过往解法。
  **不算**：模型的冻结预训练权重；一轮结束就丢的 scratchpad；**agent 无法扩展的固定 API 库**。
- **搜索（Search）算**：同时维护一个以上候选、用执行结果打分、然后选择或变异。
  **不算**：对单个候选的一条顺序修复链（那是反馈）；不做选择的一次性采样；**候选之间从不互相比较的重复提示**。

这三条正好戳破 LLM agent 领域最常见的三种夸大：把无接地的自我批评说成反馈，把上下文窗口说成记忆，把反复重采样说成搜索。

## 哪些能搬到 LLM agent，哪些不能

### 能搬的

**1. F/M/S 三条排他定义就是一份验收清单。** 几乎无损迁移。拿它逐条自评你的系统：反馈是否执行接地（有测试/verifier/真实运行结果，不是模型自述）、记忆是否跨任务持久且可检索、搜索是否维护多个候选并按执行分择优。三位齐备才叫完整循环。

**2.「固定工具集不算记忆」这条最锋利。** 判断很明确：**agent 能不能新增和改写自己的工具，才是升级点**。工具库大小不是。

**3. 五种 skill 含义的错配结构完整迁移。** LLM agent 的插件市场、skill 包、MCP 发行版正在重复机器人 skill 商店的同一个错误：分发的是静态回放，承诺的价值在本地适配层。Build / Distribute / Adapt 三层框架可以逐字借用。

**4. 入库 skill 必须带「何时适用」的守卫条件。** 这是检索能正确工作的前提，跟领域无关。没有前置条件声明的 skill，库一大就会被错误召回，skill 记忆从资产退化成噪声。

**5. 从「修复」到「搜索」是一次相变。** 单条修复链和候选种群是两个量级的机制。对 skill 演化的含义是：**必须保留多个变体、按执行结果择优，而不是原地反复重写同一段**。

**6. 挖掘近失败来稳定搜索。** 只留成功样本会让信号过稀。把「差一点就成功」的失败作为变异起点，是跟本体无关的便宜技巧。

**7. 评测协议可以直接抄两个指标。** 一是 success-vs-interactions 曲线（成功率随累积自主交互量怎么变，**报曲线和曲线下面积，不报终点单值**），二是 skill 库复用率（新任务解法里调用了至少一个已存 skill 的比例，加每个 skill 平均被调用次数）。作者对现状的批评同样适用于 LLM agent：**现有 benchmark 只测一次性能力，报的是「它成功了吗」而不是「它有没有随经验变好」**。

**8. 可解释性和安全性同源。** code-as-policy 的安全性被判为好，理由是「执行前可检视，且被约束在已审核 API 内」。这是「演化 skill 而不是演化权重」的最强论据——**skill 是可 review、可 diff、可回滚的对象，权重不是**。

**9. reward hacking 可迁移。** 只要打分器能被利用，skill 就会朝利用它的方向演化。跟机器人无关，跟 verifier 有关。

### 不能搬的

**1. 物理动作不可撤销。** 机器人打碎的杯子拼不回来，所以验证在机器人域几乎不可判定，provenance 成了安全属性而非元数据。LLM agent 的多数 skill 是可回滚的（纯生成、只读查询），沙箱重放成本近乎为零——**这让演化搜索的采样预算可以高出几个数量级**。但一旦接上支付、发信、写库、执行运维命令，不可逆性就回来了，机器人的结论重新适用。判断边界就在「有没有外部副作用」。

**2.「最高一档很稀疏」这个结论不该被同等悲观地理解。** 这是我认为全文最容易被误读的地方。机器人域的稀疏主要由**硬件循环成本**造成——自动复位、并行 rollout 这些工程量在 LLM agent 里基本消失，重置一个环境就是重开一个会话。所以 LLM agent 域没做到三合一，**是设计选择，不是物理约束**。

**3. 安全约束的性质不同。** 机器人的「不受约束探索不安全」指的是机械损伤和人身危险，是硬约束。LLM agent 的探索约束是权限边界和副作用范围，是可配置的软约束。别把机器人对探索的保守态度照搬过来。

**4. 跨本体迁移只有形式相似。** 「同一个 skill 能不能在人形和四足上跑」是形态学、动作空间、动力学的一致性问题。LLM agent 的「skill 能不能跨工具栈/模型/运行时」是**接口契约问题**。形式类似，难度来源完全不同，后者本质上好解。但有一半可搬：code-as-policy 的迁移性被绑死在感知栈，对应你的 skill 被绑死在工具/API 表面——这一条完全成立。

**5. 感知误检那层脆弱只有一半对应。** LLM agent 的对应物是上下文/状态读取错误，但**没有连续传感器噪声这一层**。你的失败是离散的、可复现的，机器人的不是。

**6. reward synthesis 那一整支不能借鉴。** 那派让 LLM 写 reward 函数或课程，但最终交付的还是**权重**。对「冻结参数 + 演化 skill」路线来说它是反例而不是样板。只有一个机制可以拆出来用：**reward reflection**——把训练统计的文本摘要回灌给 LLM 当搜索的引导信号，也就是「用聚合统计而非单次结果做反馈」。

## 这篇综述本身的局限

作者自陈四点，如实转述：

1. 组织轴（自改进程度）**刻意是 code-centric 的**。权重派和 RL skill discovery 被当成背景而非分类对象。作者承认：换一个以表示学习或数据采集为中心的视角，会画出完全不同的地图。
2. 它标为前沿的那一格（三合一）由**极新、部分是同期并行**的系统构成，跨系统 benchmark 数字不可比，所以只做定性描述不排名。
3. 领域移动太快，若干被引系统是在综述撰写期间发布的，覆盖度应当读作一个快照。
4. 「skill 经济」那整节建立在**撰写时只有一家厂商的市场**（宇树 UniStore）之上，作者把它当作提问的动机而不是成熟结论。

原报告另外指出几处边界瑕疵：

- 五级台阶其实是三个二元位（8 种组合）压成的序数标签，必然有格子被压掉；DROC 同时有反馈和记忆却被归到记忆级。这是分类体系最明显的裂缝。
- 两张表对同一个系统（RoboCoder）的自改进判定不一致。
- 语料本身有取样偏差：225 篇 landscape 工作里，仿真评测和机械臂本体占主导，**LLM 作为学习信号只占 39/225**。
- 综述提出的四个新指标**没有任何一个被实际测量过**，示意图里明确标注了「这不是实测结果」。
- 系统计数不能当领域产出统计，进入分类体系要过三道人工筛选关；被验证淘汰的候选数量没有记录，所以 PRISMA 流程不可复算。

## 如果我在做 LLM agent 的 skill 系统

1. **先用 F/M/S 三个二元位给现状打标，再逐位补齐。** 严格按排他定义自评，别放水。多数团队会发现自己停在 0 位或 1 位。
2. **每个入库 skill 强制带两样东西：何时适用的守卫条件，和一份验证记录。** 再加上前置条件、预期效果，以及 requires / provides / substitutable-by 这类关系声明。缺了这些，库越大越没用。
3. **投基础设施，不要只投 prompt。** 需要的是：一键重置的隔离沙箱、能并行跑多个 rollout 的执行器、以及**细到每次工具调用一条记录的结构化 trace**（不是一整段日志）——因为要改代码就必须定位到具体调用。机器人做不到这些是因为硬件，你没有这个借口。
4. **改代码这件事从「反复重写一份」换成「养一个小种群」。** 保留 3 到 5 个变体，全部执行打分，择优并变异。成本在 LLM agent 里低得多，这是白捡的一档提升。
5. **把两个指标接进 CI**：success-vs-interactions 曲线（报曲线下面积，不报终点）和 skill 库复用率。有了这两条曲线，「自我改进」才从一句宣称变成一个数字。
6. **把 skill 对外部世界的依赖收敛到一层显式的、版本化的能力接口。** 换工具栈时只替换接口实现，不重写 skill 库。这是对「被绑死在工具表面」这个已知缺陷的直接对策。
7. **给种群搜索加近失败挖掘**，把「差一点成功」的样本作为变异优先起点。

## 名词小词典

| 术语 | 大白话解释 |
|---|---|
| VLA（视觉-语言-动作模型） | 输入摄像头画面加一句话，直接输出关节怎么动的大模型。能力全在权重里，训完改不了 |
| code-as-policy | 不训模型，让 LLM 现场写一段调用 API 的程序当作策略。可读可改可 diff |
| skill 库 | 一个存放已验证代码的持久仓库，跨任务复用。相当于 agent 自己攒的工具箱 |
| when-to-apply guard | 挂在每个 skill 上的「什么情况下该用我」的前置条件声明。检索能否正确工作全靠它 |
| 执行接地（grounded） | 信号来自真的跑了一遍——测试结果、返回码、verifier 输出。模型自己写的评语不算 |
| 演化搜索 | 同时养多个候选方案，跑一遍打分，择优再变异。区别于盯着一个方案反复改 |
| 本体（embodiment） | 机器人的身体形态。人形、四足、机械臂是不同本体。对应 agent 的不同工具栈/运行时 |
| sim-to-real | 在仿真里训好搬到真机上。LLM agent 里对应「沙箱验证通过后放进生产」 |
| reward hacking | skill 学会钻打分器的漏洞拿高分，实际任务并没完成 |
| provenance | skill 的来源记录：谁写的、基于什么数据、怎么验证的。有副作用时这是安全属性 |
| 静默错误接地 | 输入偏离训练分布，模型不报错，只是默默做错。权重派的典型故障 |
