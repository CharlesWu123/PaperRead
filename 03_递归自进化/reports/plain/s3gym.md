# 通俗版 · S3Gym：先别吹「自我进化」，先量一量你会不会「自己教自己」

> 让大模型在七个文字游戏里自己试、自己打分、自己总结经验，然后考它有没有变强。结论很扎心：它给自己打的分和真实分数对不太上，而且就算打分准，也不代表会进步。

## 一分钟版本

- 问题：现有 agent 基准只测「模型现在多强」，不测「模型能不能靠自己的经验变强」。S3Gym 专门测后者。
- 把「从经验中学习」拆成三步分别打分：Self-Testing（自己试出证据）、Self-Judging（自己判断好坏）、Self-Improvement（把判断变成以后的正确行为）。
- 七个文字游戏都自带自动判分程序，但关键设计是：**探索的时候把真实分数藏起来**，模型只能靠自己打分来组织经验。考的时候再用真实分数验货。
- 经验有三种「存法」：把带自评分的原始轨迹直接塞进上下文、压成一条摘要笔记、或者拿去微调参数。哪种好，取决于任务长什么样。
- 最重的发现是个负结果：模型自评的准确度和它之后进步多少，相关性约等于零（-0.010）。

## 先搞清楚三个环节和三种「经验载体」

想象一个人学下棋。S3Gym 把学习拆成三步：

- **Self-Testing（自测）**：自己乱试各种走法，攒下一堆「我这么走会怎样」的经历。重点是攒下的东西有没有信息量——光输一百盘不记录为什么输，什么也学不到。
- **Self-Judging（自评）**：走完一步，自己先给自己打分：「这步我觉得能赚 3 分」。注意论文的规矩：这个分数要求是「按游戏规则推演出来的预期回报」，不是「我感觉良好的程度」。
- **Self-Improvement（自改进）**：把这些判断过的好经验和坏经验用起来，让下一局打得更好。

攒下的经验怎么存？三种容器：

- **原始轨迹（History ICL）**：把之前每一局的完整过程连同自评分，原封不动拼进上下文。细节全在，但越拼越长。
- **摘要记忆（Summary Memory）**：让模型自己把经历压缩成三段式笔记——「要保留的策略、要避免的错误、下一步的具体方向」。省地方，但压缩必然丢东西，而且万一把错的判断压缩进去了，就等于把错误固化了。
- **参数训练（Training）**：把轨迹转成微调样本，直接改模型权重。推理时什么都不用带，但改权重是危险操作，改坏了会覆写原有能力。

这三个容器哪个好？论文的核心答案：**看任务**。这是全文最实用的一条结论。

## 它想解决什么问题

现有基准都把被测模型当成一个「定死的策略」：跑一遍，打分，结束。可现实中 agent 会不断积累交互经验，真正值钱的问题是——它能不能把这些经验用起来。

更要命的是「自己给自己当裁判」这件事早有前科：LLM-as-a-Judge 一系列研究显示模型判分有偏差、校准差；还有人在 ALFWorld 上做过审计——LLM 裁判分、结果条件化的概率比、模型自身置信度，对照真实回放，识别关键步骤的能力「不比瞎猜好」。对自改进 agent 来说这是定向毒药：判断错了，会把有害经验当宝贝存下来，把真有用的扔掉。

所以 S3Gym 的思路是：别只看「最后涨了几分」，把三步拆开各自测量，这样失败能定位——是没试出有信息量的东西？是判断错了？还是判断对了但没变成行为？

## 基准怎么设计

七个游戏：Chess（国际象棋变体）、Minesweeper（扫雷）、Nullify（数值构造）、Tetris（俄罗斯方块）、Snake（贪吃蛇）、PvZ（植物大战僵尸）、Trust Evolution（重复囚徒博弈）。选游戏是因为规则程序可验证，打分客观可复现，又有多轮交互、部分可观测、延迟后果这些真实 agent 环境的特性。

每个游戏都有「探索版」和「考试版」两套配置，结构一样但参数不同：

- 扫雷探索版有两条备用命，考试版踩第一颗雷就出局；
- 贪吃蛇探索版撞墙算无事发生，考试版撞墙直接死；
- 俄罗斯方块探索版 10×10 大棋盘，考试版 8×8 更挤；
- PvZ 探索版 3×7 小战场，考试版 5×6 大战场。

加上两阶段用的随机种子完全不相交、考试时的轨迹绝不回流成学习材料——你背下某个种子下的走法是没用的，必须真提取出「这种局面该怎么应对」的规则。

防作弊的核心一招：**自动判分程序全程存在，但探索阶段不把真实分数告诉模型**。模型每步交「动作 + 自评分」，自己的分数记进历史，真实分数只存在评测系统那边。于是「自评准不准」第一次变成可以直接量化的东西——拿 11.6 万步的自评分和真实分对齐就行。

模型阵容：GPT-4o、GPT-4.1、o3-mini、Gemini-2.5-Flash、Gemini-2.5-Pro、GPT-5.5、Gemini-3.5-Flash 七个专有模型跑上下文级两条通路；另加一个 Qwen3-8B 做 20 个 checkpoint 的训练研究。

## 跑出来的效果

**自评分准不准？（98 个 run、116,117 步的对照）**

| 游戏 | 自评/真值方向一致率 | 分数幅度误差(NMAE) | 过度自信率 |
| --- | --- | --- | --- |
| Chess | 0.496（约等于瞎猜） | 0.141 | 0.365 |
| Minesweeper | 0.820 | 0.524 | 0.062 |
| Nullify | 0.827 | 0.056 | 0.170 |
| PvZ | 0.881 | 0.882（最大） | 0.032 |
| Snake | 0.879 | 0.121 | 0.110 |
| Tetris | 0.846 | 0.041 | 0.151 |
| Trust | 0.665 | 0.392 | 0.291 |

规律：奖励来自「立刻可见的局部后果」时（Tetris、Nullify），自评还行；奖励藏在对手策略或多物体状态里时（Chess、Trust），自评崩。最阴的是 PvZ：方向判断 88% 一致，但幅度误差全场最大——认得出「这步有用」，估不准「有多大用」。

**判断准，会进步吗？——最重要的负结果。** 把探索轨迹分块，算每块的判断质量，再看下一轮考试涨了多少分：全基准相关性 ρ = -0.010，基本是零。判断质量最高和最低的两批，进步幅度差也小且略负。换句话说：**局部自评准确只是进步的必要条件，不是充分条件**。会认错还不够，得会把认出的错变成能执行的规则。

**三种经验载体谁赢？看任务。**

摘要记忆赢的例子：Gemini-2.5-Flash 的扫雷改进面积从 0.000 涨到 7.794，PvZ 从 24.402 涨到 238.501；GPT-5.5 的 Chess 从 0.474 涨到 16.840。这类任务的经验能压成一句稳定规则。

原始轨迹赢的例子：GPT-5.5 的 PvZ 从 548.499 掉到 33.219（换了摘要反而暴跌）；Gemini-3.5-Flash 的 Chess 从 12.280 掉到 0.000。扫雷、PvZ、贪吃蛇这类任务依赖具体局面细节——摘要保得住「大方向」，丢掉了「这步具体怎么办」。

论文给了两个具体样本对比，特别直观：

- 好摘要（Trust 博弈）：「观察到收益结构偏向欺骗时就永远选欺骗，别做多余的对等试探」——直接对应第一步选欺骗拿了 3 分的真实反馈，改进量 +66.89。
- 坏摘要（PvZ）：「优先产阳光、早防御、用坚果拖延、覆盖受威胁的波道」——听着头头是道，但太粗，抓不住僵尸位置和阳光预算，严格分反而从 38.67 掉到 32.33。

**训练 Qwen3-8B（20 个 checkpoint）**：结果按游戏分成四档。Trust 从 0 涨到最高 30 分，19 个更新后的 checkpoint 有 18 个高于基线——这是「经验能固化进参数」最清楚的证据。Chess 和贪吃蛇只是偶尔冒头又归零。扫雷、Nullify、俄罗斯方块全程零分（可能探索期成功轨迹太少，撑不起监督信号）。最惨的是 PvZ：初始 23 分，训练后每个 checkpoint 都只有 6 分——参数更新把原来会的行为覆写坏了，典型的负迁移。

论文自己的总结：自改进「既不自动，也不均匀」；最有效的通路由任务结构决定；参数训练「在当前实现下不稳定」。

## 别被结果骗了：几个要留意的地方

**「自评准≠会进步」这个零相关，也可能是测量粒度问题。** 分块相关这种统计，信号弱或噪声大都会得出接近零的数。论文止步于相关性，没做更细的因果分析（比如按判断正误分层看哪些经验被保留）。零相关是「提示性证据」，不是「判决书」。

**游戏不是真实任务。** 七个游戏全部规则封闭、verifier 确定性。「经验能压成稳定规则时摘要有效」这个结论，放到规则会漂移、奖励会变的开放环境，未必还成立——论文对外推边界基本没讨论。

**训练研究只有一个 8B 模型。** Trust 上 0→30 的漂亮数字可能只是「小模型在封闭博弈上可教」的特例，没有跨规模、跨家族的重复实验。

**自评被操作化成每步一个数。** 真正的判断是结构化的（哪一步错、为什么、能迁移到哪）。逼模型每步报一个标量，可能测到的是「表达瓶颈」而不是「判断能力」的上限。

**主表剔除了没跑完的模型。** 论文明说只收「七个游戏结果完整」的模型，没跑完的排除掉——等于承认部分实验未完成，存在样本选择。

**专有模型全是黑箱。** 「模型差异体现在检索压缩经验的效率上」这类机制归因，全部只能从行为反推，没法看进上下文里发生了什么。

**每轮探索/评测的 episode 数、SFT 超参等细节**（学习率、数据量）在正文中没抓到，PvZ 的崩溃没法和「训练预算不足」之类的替代解释区分开。

## 如果我要用这个思路

1. **自改进回路按「试→判→存→用→考」五段埋点，判断段的输入输出都落盘。** 成本只是一条响应契约（`Answer: <动作>, Score: <自评分>`）加一个旁路记录器。有了这个，失败可以定位到环节。
2. **自评分要求「按规则推演的预期回报」这个语义，别让模型报「置信度」。** 推演式自评才能和真实奖励做数值对齐，才能量化校准。
3. **经验容器按任务选：先问「成功靠稳定规则还是靠状态细节」。** 靠波次时机、局部布局的用原始轨迹；能写成 if-then 规则的用摘要。混合负载两条通路都留着。
4. **给摘要定验收标准：必须能在新状态里执行。** 一条合格摘要要指出可复用的失效模式（不是「这局差」），并给出具体到局面条件的动作规则。可以做成生成时的 checklist 或过滤器。
5. **同时监控两个仪表，别只看自评准确率。** 论文证明自评准确率和进步幅度不相关，所以管线健康度要看「被采纳经验的实际转化率」——用了这条经验之后下一轮到底涨没涨。
6. **微调自产轨迹前先数正样本密度。** 成功轨迹太少就别急着 SFT，先回到上下文通路或主动造成功样本。
7. **训练回路必须配「防覆写」检查。** PvZ 从 23 崩到 6 且 19 个 checkpoint 全如此。每次自训练前后在同一 held-out 集上对比，回退超阈值就回滚 checkpoint。

## 名词小词典

| 术语 | 大白话解释 |
| --- | --- |
| Self-Testing | 自己乱试攒证据：重点不是试得多，是试出的东西有没有信息量 |
| Self-Judging | 每步给自己打分，语义是「按规则推演的预期回报」，不是自信程度 |
| Self-Improvement | 把判断过的经验变成以后更好的行为——S3Gym 测的最终标的 |
| History ICL | 经验存法一：带自评分的原始轨迹直接拼进上下文，细节全但费地方 |
| Summary Memory | 经验存法二：压缩成「保留策略/规避错误/下一步方向」三段式笔记 |
| Parameter Training | 经验存法三：轨迹转成微调样本直接改权重，推理时不带任何外部记忆 |
| 探索配置 / 评测配置 | 同一个游戏的两套参数：探索版宽松（有备用命、小棋盘），评测版严格 |
| verifier | 游戏自带的自动判分程序，是外部真值；探索阶段对模型保密 |
| 事件一致率 (Agreement) | 自评和真实分数「方向」一致的比例；Chess 只有 0.496，约等于瞎猜 |
| NMAE | 归一化的分数幅度误差；PvZ 方向准但幅度错得最离谱（0.882） |
| 过度自信 / 欠自信 | 自评说赚分实际亏分 / 自评说亏分实际赚分 |
| 判断-改进耦合 | 判断质量与下一轮进步幅度的相关性；S3Gym 测出约为零（-0.010） |
| AUC+ | 持续高于初始水平的面积，用来区分「持续进步」和「运气好一次」 |
| 负迁移 | 训练把原来会的行为改坏了：PvZ 训练前 23 分、训练后恒 6 分 |
| NABA | 归一化的基线以上面积，分析摘要效果时用的改进量度量 |
