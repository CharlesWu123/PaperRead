# 通俗版 · Mendel Gödel Machine：别只盯着一次失败

> 让 agent 改自己时，一次看两条记录做对比，而不是只看一次失败。

## 一分钟版本

- 这是一类「agent 自己改自己源码」的研究。模型权重完全不动，改的只是外面那层壳：prompt、控制流、工具代码。
- 以前的做法（DGM、HGM）每次改自己，只喂给编辑器**一条失败记录**。历史档案里存了大量已经花过钱跑出来的轨迹，却只被当成排行榜用来挑下一个节点。
- MGM 加了两种新改法：同一个 agent 在**多个任务**上的成败对比；不同 agent 在**同一个任务**上的成败对比。这两种对比不额外花评测预算，因为轨迹本来就存着。
- 效果：Polyglot-60 从 50.8% 到 93.2%（HGM 是 77.9%），SWE-bench Verified-60 从 68.3% 到 78.3%（HGM 73.3%）。最硬的证据是换考场实验，见下文。
- 但理论部分是循环论证，有两处自相矛盾的数字，还有一个被宣传的机制在主实验里实际上没开。结果值得看，因果解释要打折。

## 它想解决什么问题

想象你在维护一个线上服务，某次事故之后你写了条流程规范。只看这一次事故，你很容易写出这种规矩：「以后凡是改 A 模块，必须找张三签字」。它对那次事故有效，但它其实是把偶然当成了规律——真正的问题可能是「所有改动都缺回归测试」。

自改进 agent 的处境一模一样。它跑一道编程题失败了，编辑器拿到这一条失败记录，然后去改自己的源码。它没法区分两件事：

- 这是我这个壳的通病（比如从来不先读测试文件就动手写代码）；
- 这只是这道题的偶然（比如这个仓库的目录结构特别怪）。

区分不了，就容易写出只对那一道题有用的怪规则。原论文的批评很直接：自修改这一步「每一步都只以某个 agent 在某一个任务上的单条轨迹（通常是最近一次失败）为条件」，而档案「只被当作采样用的排行榜」。

关键洞察：档案里已经躺着大量对照材料。同一个 agent 跑过 10 道题，成 7 败 3——这 3 次失败有没有共同点？另一个血统的 agent 在同一道题上做对了——它做对时做了什么我没做？这些信息全都是已经付过费的副产品。

## 核心思路：三种改法

MGM 把「改自己」这一个动作拆成三种，外层的选节点、评测、扩展框架完全沿用 HGM。

**第一种：克隆突变（Clonal mutation）**。就是老办法：拿一条失败轨迹，诊断，改。类比：看一次事故写一条规范。它在 MGM 里被保留成兜底，只在档案还太小、凑不出对照的时候用。采样权重只有 0.10。

**第二种：反应规范突变（Reaction-norm mutation）**。把同一个 agent 在两个不同任务上的轨迹一起塞进编辑器，其中至少一条是失败。指令是：先找出这几条轨迹**共有的**行为模式，再做一个**通用**改动。

类比：把最近三次事故的复盘报告摊在一起看，才能看出「我们每次都是在没有回归测试的情况下上线」。单看一次，你只会看到那次的具体触发点。

真实例子：Polyglot 上最优 agent 的第 9 号节点就是这么来的，它把原来「一轮直接写代码」的流程换成了两阶段——第一阶段先抽出一份精确的契约计划（类签名、构造函数、方法定义、原文照抄的错误消息），第二阶段严格按计划实现再自查。第 16 号节点又加了一个最多五轮的「跑测试—读输出—修」循环。这都是流程级的重写，不是打个补丁。

**第三种：跨血统杂交（Cross-lineage hybridization）**。同一道题，两个不同血统的 agent 都跑过，且**不是双双做对**（双双做对提供不了对照）。把两条轨迹一起给编辑器。

类比：隔壁团队解决了跟你一样的问题，你去看他们怎么做的，然后用你自己的技术栈实现一遍。注意是「实现一遍」，不是把他们的代码拷过来。

方向有硬规则：如果恰好一方做对了，被改的是**失败的那一方**，成功的那一方只当参考素材，产生的子节点挂在失败血统下面。论文的意图很明确——目标不是继续改那条已经成功的血统，而是让失败的血统继承成功轨迹里那个可迁移的行为。如果两边都失败，就用表现更好的那条作主编辑对象，另一条当反面对照。

真实例子：最优血统的第 2 号节点就是杂交产物，加的只是一段 prompt 指令——先用编辑器工具看 stub、测试、类层次，只实现仓库里已定义的接口。所以杂交落地时也可以只动 prompt。

**为什么后两种叫「比较信号」**：因为它们的价值不在于给编辑器更多数据，而在于**缩小怀疑范围**。作者自己的解释很到位：比较证据并不是让编辑器变强了，而是降低了诊断的不确定性——编辑器要在一个更小、更干净的候选缺陷集合里搜索。第二种固定 agent、变任务；第三种固定任务、变 agent。就是控制变量法的两个方向。

**孟德尔这个类比，是真指导还是只用来起名**：介于两者之间，偏向后者。真指导的部分是「受控比较」这个方法论确实切出了两个正交维度，并且直接决定了两个算子的触发条件和证据结构，不是事后贴标签；「反应规范」也是 1909 年就有的真实生物学概念。但生物学的内核基本没搬过来：生物学里的杂交是两套基因组重组，MGM 明确说了它**不做代码拼接**，实际是「单亲编辑 + 另一亲当参照」，这更像「看着邻居长得好，自己改自己」。等位基因、显隐性、分离定律全都没有对应物。伪代码里的算子权重参数还写作 A/B/C，正文才改成 CM/RM/CH，说明机制先存在、命名后统一。把所有生物学词换成「跨任务证据算子」「跨血统对照算子」，方法和结论一字不用改。

## 最有说服力的证据：换个考场还灵不灵

主实验的涨点有个天然嫌疑：agent 在 Polyglot 上演化了 200 次评测，会不会只是把 Polyglot 这 60 道题的套路背下来了？

所以作者做了这件事：在 Polyglot-60 上演化出 agent，然后**冻住这个壳**，直接拿去考两个从没见过的基准。

| 换的考场 | 演化前 | HGM | MGM |
|---|---|---|---|
| SWE-bench Pro | 16.7 | 13.3（−3.4） | 26.7（+10.0） |
| SWE-bench Multilingual | 41.7 | 43.3（+1.6） | 55.0（+13.3） |
| 平均 | 29.2 | 28.3（−0.9） | 40.9（+11.7） |

大白话解释 SWE-bench Pro 那一行：老方法辛辛苦苦演化了一轮，换个考场之后**比不演化还差**（16.7 掉到 13.3）。这说明它学到的东西是对着 Polyglot 那批题的失败模式量身定做的，属于过拟合——出了那个考场就是负资产。MGM 反而从 16.7 涨到 26.7，说明它学到的是「先把测试读成严格的行为契约再动手」这类**通用工作习惯**，换什么题都用得上。

为什么这比主实验的涨点更有说服力：主实验里高分可以来自「刷熟了这批题」，而迁移实验里，任何题目特异的技巧都会失效甚至变成拖累。老方法的平均是负数，这个负号本身就是「单轨迹自修改会过拟合」的直接证据，比 MGM 涨了多少更有信息量。

还有一个换底座的实验：壳在小模型上演化，换成更强的推理模型，涨幅仍然保留（DeepSeek-V4-Pro 上 45.0 → 75.0），并且 MGM 的壳配 DeepSeek-V4-Pro 在完整 225 题 Polyglot 上拿到 96.89%。

## 跑出来的效果

主实验，底座 Qwen3.6-35B-A3B，预算严格对齐（200 次评测 + 24 次扩展）：

| 基准 | 演化前 | HGM | MGM |
|---|---|---|---|
| SWE-bench Verified-60 | 68.3 | 73.3（+5.0） | 78.3（+10.0） |
| Polyglot-60 | 50.8 | 77.9（+27.1） | 93.2（+42.4） |
| 平均 | 59.6 | 75.6（+16.0） | 85.8（+26.2） |

MGM 相对 HGM 净赚：SWE-bench 上 +5.0 点，Polyglot 上 +15.3 点。耗时几乎一样（平均 68.12 小时 vs 68.61 小时），token 消耗也在同一量级，所以不能用「花了更多算力」来解释。

全量 Polyglot 225 题复核是 210 题解出 = 93.3%，跟 60 题子集上的 93.2% 基本一致，各语言分布均匀（C++ 25/26、Go 36/39、Java 43/47、JavaScript 46/49、Python 33/34、Rust 27/30），说明不是靠特化某种语言。

两种新改法各自值多少（Polyglot-60 消融，同样 200 次评测）：

| 变体 | 准确率 | 掉了多少 |
|---|---|---|
| MGM 完整 | 93.2 | — |
| 去掉反应规范突变 | 79.7 | −13.5 |
| 去掉跨血统杂交 | 74.6 | −18.6 |

跨血统杂交更关键。作者的解释是它能把有用的演化信息在迭代之间保存和复用。有一个作者没点出的细节：去掉杂交之后的 74.6 其实**略低于 HGM 的 77.9**，也就是只剩「单轨迹 + 反应规范」时未必稳赢老方法。

反直觉的附加结果：换成更大、更偏 coding 的 Qwen3-Coder-Next-80B-A3B 做底座，SWE-bench Verified 上只演化到 41.7%（HGM 40.0%，演化前 33.3%），远低于小一些的 Qwen3.6 的 78.3%。原因是 Qwen3.6 在通用推理项上全面更强（GPQA +11.51、HMMT +20.49 / +13.53 等）。「决定该改什么」是一个诊断和抽象问题，不是代码补全问题。

## 别被结果骗了：几个要留意的地方

**理论部分是循环论证**。论文证了一个命题：两个新算子的修复成功率高于老算子。但证明反应规范突变那一步，前提直接写成「两次失败共享同一个复发的因果缺陷」。这恰恰是需要被验证的结论本身——「多次失败里真的存在共性问题」正是整篇论文要论证的事，不能拿来当前提。作者把它列为「可靠比较假设」，态度诚实，但问题没解决。

**关键参数是手填进仿真的，不是推导出来的**。仿真里有一个参数专门表示「新算子的诊断优势有多大」，取值 1.0 / 1.2 / 1.5 / 2.0，主图取 2.0。这个数字是外部注入的自由参数，不是从命题算出来的。所以那些漂亮的仿真曲线严格来说只验证了一件事：**如果**诊断优势存在，那么 MGM 收敛更快。至于诊断优势到底存不存在，仿真一个字都没证明，只有真实实验的消融表算是支持。

顺带一提，理论里那套「基因型是 100 位二进制串、每位独立可修、离最优解的汉明距离就是进步度量」的设定，在真实 agent 上大概率不成立：真实的壳里 prompt、控制流、工具是强耦合的，加一个两阶段流程会改变后面所有 prompt 的语义位置，不是翻转一个比特；而且真实空间没有已知最优点，每次编辑还可能新增维度（新工具、新文件），汉明距离在那里根本没定义。作者自己也在局限里承认了这点。

**有两处自相矛盾的数字**。附录里的正文写「对应的 Qwen3.6-35B-A3B 设置下，MGM 在 SWE-bench Verified-60 上达到 61.7%」，而 Table 1 和同一节的 Table 7 都写 78.3%。78.3 出现两次、61.7 出现一次，应以表格为准，但这属于论文自身没对齐。

**一个被宣传的机制在主实验里等于被关掉了**。论文有一个设计叫「失败任务池」：把暴露过失败的任务攒起来，给它们更高的采样权重，作用之一是**故意制造不同血统之间的任务重叠**——因为跨血统杂交要求两个 agent 跑过同一道题。听起来很关键。但超参表里那个加权系数是 1.0，也就是加权等于没加权，这个机制在主实验配置里并没有真的开启。所以杂交算子的高可用性更可能来自 HGM 式评测调度天然产生的重叠，而不是论文声称的这个设计。机制归因存疑。

**其他要打折的地方**：真实实验**没有报告多个随机种子**，作者自己承认。所以 SWE-bench 上那 5.0 点的差距在没有方差估计的情况下解释力有限（Polyglot 上 15.3 点差距比较大，可信度高一些）。档案只有 25 个节点（1 个根 + 24 次扩展），很小；比较信号在更大档案上是变密还是变噪，没有数据。另外这套东西冷启动没优势：档案小、任务重叠稀疏、还没积累出有信息量的失败时，它退化成老方法。最后，好证据不等于好编辑——论文只改进了喂给编辑器的证据，不保证改出来的代码正确、通用、可维护，失败的编辑照样烧预算。

## 一个有意思的发现：演化出来的其实是「经验」不是「代码技巧」

看最终演化出来的产物，本质上是一套工作流和经验，不是底层的代码奇技淫巧。

论文把演化出的改动描述做了语义可视化：MGM 的产物密集聚在三个主题上——精确提取测试契约、遵守 API 契约、实现前先做验证。HGM 的产物则散在各处（迭代测试、API 对齐、上下文发现、辅助工具各自为政）。杂交案例里被传递的那个能力，作者干脆命名为「test-contract skill」：实现前先把测试读成严格的行为契约，保留精确的公开 API、期望值、错误消息。它从一条血统传到另一条血统，接收方也解出了原来做不出的题。

作者顺手给了一个判断泛化性的操作性标准：不看措辞是否宏大，而看这个演化出的 skill **是否脱离了它诞生时那道具体题目，变成一个对一大类未来任务都可复用的流程**。

对做 skill 自进化的人意味着什么：MGM 名义上在演化源码，实际产出的东西跟一份写得好的 skill 文档没有本质区别。反过来说，这两个「比较信号」算子搬到 skill 演化上比搬到源码演化上更容易——skill 演化系统本来就在跑批量 rollout 并保留判定结果，「同一份 skill 在多个任务上的成败剖面」是现成的，而且一次 rollout 远比一次 SWE-bench 评测便宜。而反应规范突变正好针对 skill 演化最典型的失效模式：单条失败驱动的文本改写会把偶然错误写成永久规则。要注意一个 MGM 没有的风险：文本 skill 太容易被直接抄袭合并，从而丧失血统多样性、退化成单点，所以维持多样性的约束不能只搬算子。

## 如果我要用这个思路

1. **把自修改的输入从「一条轨迹」升级成「一个对照结构」**，并在指令里显式要求：先找共同或差异模式，再做通用改动。这是零额外评测成本的改动，消融显示两个算子分别值 13.5 和 18.6 个点。
2. **档案不要退化成只存分数的排行榜**。最小字段集：agent 版本 ID、父节点 ID（血统）、任务 ID、完整轨迹、二值结果。有这五样，两个新算子的触发条件都是一次索引查询。
3. **主动制造任务重叠**。让不同血统在同一批「已知能暴露问题」的任务上被评过，而不是各自随机采样，否则档案里根本不存在可比的对照。注意论文自己把这个加权设成了 1.0，最佳权重原文没给，得自己调。
4. **混合的方向写成硬规则，不要让模型自选**。恰好一方成功时，编辑失败方、成功方只当参考素材，子代挂在失败血统下；双方都失败时用表现更好的一方当主编辑对象。这保证能力从强血统流向弱血统，而不是反过来把好血统改坏。同时不要拼接代码或文本：参考轨迹只进上下文，产出必须是目标 agent 在自己代码库上的重新表述。
5. **选最终产物用置信度加权，不要取最高分**。论文的做法是跳过「分数 1.00 但只评过 4 次」的节点，选「0.91 但评过 35 次」的。小档案里最高分几乎总被评测次数最少的节点占据，直接取最大值会系统性选到噪声。
6. **底座选型看通用推理，不看 coding 榜分或参数量**。这是引入比较信号的隐性代价：证据越丰富，对底座的诊断和抽象能力要求越高。顺便，自修改和评测要跑在无网络、宿主文件系统只读的沙箱里——一次错误的自编辑会被后代继承，污染是持久的。

## 名词小词典

| 术语 | 大白话解释 |
|---|---|
| scaffold（外壳） | 包在大模型外面那层代码：prompt、控制流程、工具函数。模型权重不动，改的全是这层 |
| genotype（基因型） | 在这篇里就是「一份可执行的 agent 源码 + 它的外壳」 |
| 自修改算子 | 「怎么改自己」的一种具体做法。这篇提供了三种 |
| 克隆突变 | 老办法：看一条失败记录，诊断，改 |
| 反应规范突变 | 同一个 agent 在多个任务上的成败一起看，找共性问题 |
| 跨血统杂交 | 同一道题上，看另一条血统怎么做的，用自己的方式重写一遍。不拷代码 |
| 血统（lineage） | 演化树上的一条祖先链。一个 agent 改出来的后代属于同一血统 |
| 档案（archive） | 存所有生成过的 agent 版本和它们跑出的轨迹的库 |
| 比较信号 | 档案里已经付过评测成本、但从来没被送进编辑器的对照材料 |
| 失败任务池 | 曾暴露过失败的任务集合，用来给采样加权、制造血统间的任务重叠 |
| best-belief agent | 最终交付的 agent 选法：不选分数最高的，选「分数够高且评测次数够多」的 |
