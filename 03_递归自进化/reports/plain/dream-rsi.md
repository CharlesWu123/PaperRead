# 通俗版 · Dream-RSI：让 AI 靠「做梦」学会怎么更好地探索

> 不训练模型，也不改任务代码，只改「怎么找答案」这一小段策略；改它靠的不是真跑，而是把以前跑过的记录当成沙盘，在里面低成本地推演。

## 一分钟版本

- 模型权重全程不动，任务代码也不动。唯一被反复改写的，是**「下一步该往哪儿探索」这段策略代码**——先开哪个方向、同时开几个、什么时候收手。
- 核心点子：**已经做完的一轮探索，本身就留下一棵「决策树」**（每个节点是一次尝试 + 它的真实结果 + 当时的工作区快照）。这棵树可以直接当**沙盘/模拟器**用——换一条策略，无非是在树上走另一条路，读一读沿途已经存好的结果就能打分，不用重跑任何东西。
- 于是流程变成三步循环：**真跑一轮（在线探索）→ 把这轮的树存进沙盘池 → 在沙盘里「做梦」，把一堆候选策略快速比一遍，挑最好的上线**。
- 作者叫它「回放模拟器」或「世界（world）」。注意：这个「世界」**不是学出来的，而是历史记录本身**，所以它只能重排「已经看过的分支」，不能凭空造出新方向。
- 成绩：跨 4 个领域 9 个任务。在 Lasso 算法发现上比 SimpleTES 少用约 162 倍调用；在内核优化上达到同样性能少用 2.43 倍/1.79 倍 generation，或在同样预算下性能高 2.09 倍/1.44 倍；数学题三题里一题领先、一题追平、一题落后；把 Terminal-Bench 2.1 的 harness 从 0.7247 提到 0.8090。

## 它想解决什么问题

自进化 AI 的通用套路是「提方案 → 评估 → 把反馈折进下一轮」，反复转圈。可当目标变难，找答案需要在巨大的可能性里**长程搜索**，动辄几千轮。这时候真正卡脖子的已经不是「想不想得出好方案」，而是**「怎么安排探索」**——先试哪个方向、哪些并行、什么时候放弃。

问题是，怎么探索这件事**通常是人手写死、全程不变的**。写死了就不会从经验里学，容易反复把算力砸在没戏的方向上。

那能不能让 AI 自己学着优化「怎么探索」？能，但很贵。因为：

1. **反馈又慢又贵。** 评价一条探索策略好不好，得看它在几十上百轮里怎么塑造整个搜索过程，不是跑一次就知道。
2. **可选项太多。** 策略空间巨大，得试很多条才知道哪条好。

每条策略都要真跑一遍长长的流程才有信号，成本高到「自改进的圈」根本合不上。

Dream-RSI 要解决的就是这个：**在真跑之前，先便宜地把候选策略筛一遍。**

## 核心思路

想象你在一个陌生大迷宫里找宝藏。第一次进去你瞎撞，撞了很多死胡同，最后摸出一条路——**但你顺手把整张地图画出来了**。

下次再来，你就不用瞎撞了：盯着地图规划，跳过已知死胡同，比较几条路线，甚至能试「如果我先走这边会怎样」——**完全不用真的再走一遍**。

这就是 Dream-RSI 的全部直觉。它把「以前探索留下的记录」从**一段只能读的历史**，变成**一个能反复推演的沙盘**。

用到的类比其实来自强化学习里的「世界模型」（World Models / Dreamer）：先学一个环境的模型，然后让策略在模型里「想象」轨迹来改进，而不是在真实环境里反复试。Dream-RSI 把「学出来的模型」换成了**「记录下来的树」**——更土，但零误差、零额外成本。

### 具体怎么转

一个循环三步（对应论文 Figure 1）：

1. **在线探索**：当前策略指挥一个固定的发现 agent 去真干活，边干边把过程记成一棵树。树上每个节点是一次尝试：它的父节点是谁、工作区什么样、尝试内容、以及评测分数。
2. **建沙盘**：把记录下来的树存进「沙盘池」。
3. **做梦改进策略**：让同一个 agent 在沙盘里**模拟**一堆候选策略——每条候选无非是「换一批分支、换个顺序、换并行度、换更早收手」。因为沿途结果都是现成的，**打分只要读记录，不用重跑**。挑出最好的那条，上线，进入下一轮真探索。

关键限定（一定要记住）：沙盘是**历史记录本身**，不是会推理的模型。所以「做梦」能做的是**在已经探索过的分支上重新分配算力**，**造不出全新的方向**。新方向只能靠在线探索去开。

### 三个小设计

- **在线和离线用同一个「动作接口」。** 策略代码在真实世界和在沙盘里行为完全一致，只是状态转移一个「真执行」、一个「重放」。这是沙盘分数能预测真实表现的前提。
- **沙盘里怎么给策略打分。** 两个部分相加（相减）：一是「质量–成本」的帕累托前沿面积（用更少调用拿到更高质量就加分），二是**惩罚串行**（能并行的却一个个串着跑就扣分）。这样策略不会为了分数无脑堆算力，也不会为了省成本干脆不探索。
- **候选里永远留着当前版本。** 因为「现在这条」也算候选，所以**新策略在沙盘分上永不比旧的差**。注意这个「只升不降」只保证在沙盘里，不代表真实世界也一定变好——这是最需要留意的一处（见下面「别被结果骗了」）。

## 跑出来的效果

用 4 个领域 9 个任务测。对照方法叫 **Recursive Fixed Exploration**，是刻意设计得**极其公平**的基线：发现 agent、评测器、初始化、每轮预算、甚至起始策略**全都一模一样**，唯一区别是它从第二轮起**策略保持不变**，而 Dream-RSI 会更新策略。

**内核优化（KernelBench，4 个任务）**
- VGG16、LayerNorm：达到相当性能，分别少用 **2.43 倍 / 1.79 倍**的 generation。
- ConvDiv、ConvMax：在**同样预算**下性能高 **2.09 倍 / 1.44 倍**。
- 超过强基线 PACEvolve（给了它 48 小时墙钟上界）。

**Lasso 算法发现**
- 相比 SimpleTES 报告的 51,200 次 generation，Dream-RSI 用约 **162 倍（Pro）/ 27 倍（Flash）更少**的调用，下游平均运行时间还更低。
- **但要小心**：SimpleTES 用的是另一个模型底座（gpt-oss-120b），这个「162×」是跨底座的比较，不是同条件对照。
- 同条件下（对 Fixed Exploration）：Pro 317 次调用 vs 550、平均 2931ms vs 3587ms；Flash 1879 vs 3200、平均 2350ms vs 2517ms。两个底座都是更省调用、平均更快。

**数学题（三题）**
- Sum–Difference：**领先**（1.145427，超过 SimpleTES 和 Fixed）。
- Circle Packing：**追平**最强报告值（这题已经饱和）。
- Autocorrelation（越低越好）：**落后**于 AlphaEvolve、SimpleTES。论文只说「保持竞争力」。

**Harness 优化（Terminal-Bench 2.1，89 个任务各跑 2 次）**
- 把种子 harness（Terminus-Kira）从 **0.7247 提到 0.8090**，超过 Claude Code（0.75）和复现的 Meta-Harness（0.79）。
- 这项**没有做公平对照**，理由是再做一次完整搜索成本超过 10 万美元。所以只有端到端数字，没法归因到「策略更新」这一个变量。

## 消融实验说了什么（这部分最有信息量）

**一、历史攒得越多越好用。** 在 ConvDiv 上，用**全部历史**当沙盘 → 性能 1.90；只用**当前轮** → 1.59。攒多个「世界」能学到更通用的策略，避免过拟合到单一世界而变得过度保守。

**二、「回放历史」比「把历史写成提示」强。** 一个很自然的替代方案是：把历史总结成几句方向性建议，塞进提示词里给 agent 参考。结果——**给两种方法都加这种提示，最终性能反而都下降了**。作者说显式方向提示可能**限制**了探索。这条很反直觉：说明 Dream-RSI 的收益不是「多喂了点上下文」带来的，而是「能在沙盘里真推演」带来的。

**三、策略确实学会了调节算力。** 在 ConvDiv 上，每轮评估的尝试数是这样变的：110 → 110 → 87 → 80 → **50** → 92 → 80 → 91 → 86。也就是：性能在涨的时候它**主动省算力**（降到 50），一旦进度停滞，它又**重新加大探索**。这比单看最终分数更能说明「策略真的学到了东西」。

## 别被结果骗了：几个要留意的地方

### 一、「只升不降」的保证只发生在沙盘里

论文证明：新策略在**沙盘分**上永不比旧的差（因为旧策略也在候选里）。听起来很稳，但**沙盘就是系统自己过去的记录**。

打个比方：这有点像「学生自己出卷、自己批卷，还只在自己出过的题上考」。这不必然坏（任务本身的评测器是外部客观的，沙盘只是重排），但它意味着——**「沙盘分单调不降」和「真实在线表现单调不降」之间，没有严格的理论桥**。论文用那个公平的单变量对照来**经验性地**证明真实世界也变好了，做法是对的；但「沙盘分能不能预测在线收益」这件事，论文**没有单独量化**。

### 二、「162×」是跨底座的数字

很有传播力，但底座不同（SimpleTES 用 gpt-oss-120b）。同条件对照下的省调用幅度大约是 **1.7 倍**。正文里作者标注了这一点，但摘要里的大数字容易被当成同条件结果。

### 三、Lasso 在 Pro 上的「平均更快」是单一数据集拉动的

论文自己承认：Pro 配置下，平均改善**主要来自 RCV1 这一个数据集**，**其余五个数据集其实都更慢**（比如 Gisette 2841ms vs 1861ms）。只是因为 RCV1 的绝对数值大（14616 vs 19550），**算术平均**被拉了过去。Flash 配置倒是实打实的 6 个里 5 个更好。所以「平均更快」这个结论**对底座敏感**。

### 四、数学题是三选一落后

Autocorrelation 上 Dream-RSI 不是最好的。论文措辞准确（「competitive」），但读者容易把「competitive」读成「领先」。

### 五、规模还小，「递归」是有界的

在线轮数只有 5–10 轮，每轮候选策略 4 个，单轮预算上限 110 次调用。自改进循环只转了 5–10 圈，离「开放式长程自改进」还有距离。

### 六、暂时还复现不了

论文附录把提示词、任务定义都给了，透明度不错；但代码仓库 README 显示 **codebase 和复现脚本还在准备中**，发现出来的程序也在准备中。端到端复现暂时做不了。

## 如果我要用这个思路

1. **把「怎么探索」单独剥成一段可替换的代码。** 别把探索逻辑散在提示词和工作流里。它应该能单独评估、单独回滚。

2. **把历史记成「树」，别只记成「文本」。** 每个节点存：父节点、工作区快照、观测、分数。这样一份历史能同时干三件事——当上下文、当沙盘、当审计记录。只当提示词文本就浪费了。

3. **让在线和离线共用同一套动作接口。** 只切换「真执行 / 重放」。这是沙盘有意义的前提。

4. **meta 目标要同时算「质量」和「成本」，并显式惩罚串行。** 只优化质量会无脑堆算力，只优化成本会不探索。

5. **候选里永远留着当前版本。** 这样每轮更新「在沙盘分上只升不降」，低成本拿到安全垫，不用靠回滚兜底。

6. **把「每轮花多少算力」做成可学的自适应行为。** 爬升期省、停滞期加，这个节律可以主动设计进目标里。

7. **跨底座的对比只当参考，同条件对照才算数。** 想复现因果结论，只有「除了被测变量以外全一样」的基线能撑得住。

## 名词小词典

| 术语 | 大白话解释 |
| --- | --- |
| RSI（递归自进化） | 系统改进自己，而且改进后的系统能更好地改进自己，一圈圈转 |
| 探索策略 / exploration policy | 「下一步往哪儿找、同时找几个、什么时候停」的那段控制器代码 |
| 发现树 / discovery tree | 把一轮探索记成一棵树：每个节点是一次尝试 + 结果 + 当时的工作区快照 |
| 回放模拟器 / 世界 / replay simulator / world | 用「以前的发现树」当沙盘，可以反复在上面推演不同策略，不用真跑 |
| 做梦 / dreaming | 在沙盘里试一堆候选策略、快速打分，挑最好的那个 |
| 在线探索 / 离线做梦 | 在线 = 真跑真评估；离线 = 在历史记录上重放 |
| 预算偏好 ρ | 一个旋钮，控制策略「多省 vs 多花」算力的倾向；扫一遍看整条质量–成本曲线 |
| Pareto 前沿 / hypervolume | 质量–成本的最优边界；前沿下方的面积越大，说明又省又好 |
| 并行度惩罚 | 能并行却串着跑就扣分，鼓励把独立的好候选批量并跑 |
| 发现 agent 调用数 | 成本度量：一共让发现 agent 干了几次活 |
| generation（生成） | 一次「提方案」动作；generation 数少 = 更省 |
| held-out 数据集 | 发现时没见过、专门用来测泛化的数据 |
| harness（外壳） | 模型外面那一圈工程：信息怎么存、怎么取、怎么呈现给模型 |
| Terminal-Bench 2.1 | 一个终端任务的评测集，本文用来衡量 harness 好坏 |
| 单调性保证 | 论文证明新策略在沙盘分上不比旧的差——注意只在沙盘里成立 |
