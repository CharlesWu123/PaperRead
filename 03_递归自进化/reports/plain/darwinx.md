# 通俗版 · DarwinX：不动模型，只让 agent 的「外壳」自己进化

> 模型一个字节都不改，只让 agent 的提示词和工具自己进化，四个基准平均涨约 17 分。

## 一分钟版本

- 大模型权重完全冻结。所有涨分都来自 agent 的「外壳」（harness）：提示词、skill 文档、工具、控制流。
- 不再养一个不断被改的 agent，而是养一群变体，成绩记在一棵「家谱树」里，好苗子还能互相嫁接。
- 准入规则是核心贡献：一个改动只有「至少解决了新任务」且「把老任务弄坏的总量很小」才准进树。
- 打分不靠模型自评，靠每个基准自带的自动判分程序。不需要标准答案，也不需要人挑赢家。
- 结果里 Terminal-Bench 2.1 的 75.5% → 83.2% 比较扎实；WebArena-Infinity 的 43.5% → 93.0% 数字很漂亮，但起点本身有问题，得打折看。

## 先搞清楚什么是 harness

把大模型当发动机。harness 就是变速箱、方向盘、仪表盘和后视镜——发动机不换，换的是驾驶舱。

论文把 harness 明确切成两层：

- skill 层：提示词、记忆、蒸馏出来的经验文档（「遇到 X 情况就先做 Y」）。
- code 层：工具实现、控制流、agent 的主循环。

这两层都允许被改。有意思的是，实验里真正长出来的东西几乎全在 skill 层：Terminal-Bench 2.1 上新增了 7 个 skill，WebArena-Infinity 上新增了 4 个浏览器 skill 加一条提示词规则改写。作者拿来当亮点展示的 code 层改动，一个都没有。

也就是说：就算你把源码改写权限交出去，选择压力最后也主要落在「写给模型看的文字」上。

## 它想解决什么问题

现在这批「agent 自我改进」的工作，内循环长得都一样：跑一批任务、反思失败、提一个改动、用某个信号判断收不收。DarwinX 说内循环已经趋同了，没解决的是外面那层「谁有资格留下来」的选择过程。

单血统（只维护一个当前最优 agent，一路往下改）有两个病：

第一，路径依赖。就像一个只有一条 commit 链、还不断 amend 的仓库：第三次改动定死了后面所有改动的上下文，等你发现方向错了，已经没有分岔点可以回去了。SICA 那套系统自己就报告了「改了几次就停在平台期」。

第二，跨任务互相踩。修好了 A 类任务，B 类任务悄悄坏了。论文原话是：很多提示词和工具改动在一小撮任务上赢，放到全量基准上是亏的。任务分布越宽这个病越重。

对现有系统的具体批评：

- HarnessX 的做法是把任务族隔离开、变体互不干扰。干扰是压住了，但每个专家被锁在自己血统里合不起来，而且每次都「只掉一点点、不超阈值」的小回退会一直累积。
- DGM 一次只变异一个父本，跟父本比分。问题是没有合并算子，解互补任务的两条血统永远不会汇合；而且「涨分」不附带「保住原有能力」的义务。

所以 DarwinX 的自我定位很克制：档案（保留所有变体）不是它的贡献，档案只是地基，贡献是地基上的准入规则。

## 核心思路：养一群而不是养一个

三件事，一起才成立。

**一棵家谱树。** 每个节点是一个 harness 快照，附带：这次改了什么（diff）、每个任务分别考了多少分、试验过程的证据、蒸馏出的经验。关键性质是节点可以隔很久之后被重新捡起来继续长——不像单血统只能一路往前。

**只准加，不准换。** 编辑要求是增量的。一条血统是在累积能力，而不是在做一连串「拆东墙补西墙」的平移重写。

**准入规则：只接纳不让老任务变差的改动。** 这是全文最该记住的一条。用工程话讲就是：改代码必须跑全量回归测试，只有「新增了通过的用例」且「挂掉的用例总量在很小的容忍范围内」的改动才准进主干。

这里有两个容易忽略的细节，都很实用：

- 回退量是**加起来**算的，不是取最大值。如果你的门槛是「单个任务最多掉 5 分」，那一次掉 4 分、掉 3 分、掉 4 分的改动会全部放过去，总量却很难看。这正是作者批评 HarnessX 时说的「小回退会累积」的对症设计。
- 准入宽松，采信严格。这是「两档速度」：想试一个改动，门开得比较大（否则血统会在互补变体出现之前就被冻死）；但要成为后代的父本、要进最终报告，必须在更高采样次数下重测，还要再跑一遍「老任务复查」——拿这条血统原本已经解决的任务重新抽样验一遍。作者原话：对尝试宽容，对信任严格。

**血统重组。** 两条血统各自解决不同的任务，就把各自的 diff 从共同祖先上合起来。接受条件很硬：合并结果必须覆盖所有父本赢下的任务的并集。合并只允许加覆盖，不允许拿一个换一个。

**排序按累计涨幅，不按当前分数。** 因为不同变体是在不同任务子集上筛出来的，绝对分不可比。一个「在已经改进过的父本之上再加了真实改进」的节点，即使它自己那个子集更难、分数更低，也该排在前面。另外留一个小概率去种群里随便捞一个，防止过早收敛。

## 打分的人是谁：为什么这篇的结果比较可信

fitness 全部来自每个基准**自带的自动判分程序**，指标是逐任务的通过率（跑 k 次取平均）。摘要写得很直接：没有标准答案，没有人工挑赢家。演化循环从头到尾不读基准的参考解，唯一的监督就是判分结果加 agent 自己跑出来的轨迹。

这一点为什么重要：同类工作的普遍软肋是用大模型给自己打分。模型偏爱自己写的东西，这种偏差会被搜索过程一轮一轮放大——搜索最终优化的是「让评委高兴」，不是「把活干对」。用外部判分程序就没这个漏洞。

而且这批基准的分数本身抖动就不小（论文引的数据：SWE-bench Verified 上 pass@1 有 2.2 到 6.0 分的波动，这个量级往往就等于一次被接受的编辑）。DarwinX 的态度不是降噪，而是校准每个决策需要多少证据：试一下只要一点证据，写进结论要很多证据。

唯一的妥协：WebArena-Infinity 的演化阶段用了大模型评委给合成任务打分。但最终报告用的是真实任务上的确定性判分程序。等于把「评委有偏」的风险转成了「代理指标不准」的风险，而这个风险是可以被最终指标检验的。后面会看到，这个风险是真实存在的。

## 跑出来的效果

四个基准按「演化信号和最终测试的分离程度」从紧到松排列，这个排序本身就是论证结构。

**Terminal-Bench 2.1（同一批 89 个任务上演化再考）：** 同模型对比 75.5% → 83.2%，涨 7.7 分。换更强底座能到 84.7%，作者称当时超过榜首 Claude Code（83.8%，而且用的算力档更低），比 OpenAI 自家同档单 agent 参考（81.8%）高 2.9 分。同底座的中性 harness Terminus 2 是 78.0%。

涨分不是靠多烧算力堆出来的，有两条证据：Terminus-2 在更高算力档只有 78.0%，还是低于 DarwinX 的 83.2%；而且多花的算力是定向的——6 个从失败翻成解出的任务上，轮数约翻倍（22 比 11）、token 约四倍（380K 比 89K），而在双方本来都能解的 69 个任务上算力几乎没动（13 比 12 轮）。

「只加不减」也有经验痕迹：88 个可配对的任务里，36 个变好、43 个不变、9 个变差。按分类看，机器学习与科学计算 60.1% → 74.9%，数据/数据库 83.9% → 97.8%，运维 92% → 98%，只有安全类 85% → 84%（作者称在噪声范围内）。

**TerminalWorld（94 个任务上演化，41 个没见过的任务上考）：** 68.3%（28/41），同模型对比是 25 → 28 个任务。这一节最值钱的其实是它暴露的过拟合：训练子集分数从 0.505 一路饱和到 1.000，而没见过的任务只有 68.3%，差 31.7 分。更有意思的是最贴合训练分数的变体并不是泛化最好的——四个高分专家分别解出 24、25、26、27 个，合并之后解出 28 个，超过任何单个。这是「为什么要留一整个档案而不是只留当前最优」最直接的证据。

**WebArena-Infinity（300 个合成任务上演化，1260 个真实任务上考）：** 审计后通过率 43.5% → 93.0%，涨 49.5 分。同时非法成功轨迹从 120 条降到 17 条，确认违规率 23.5% → 1.4%。逐应用看，涨最多的是需要改状态的：Elation 处方 20.0% → 95.0%，Gmail 25.0% → 98.3%。

这个 49.5 分是全文最扎眼的数字，可疑之处下一节讲。先说作者做了哪些防护：合成任务来自一条独立的、只读各应用说明文档的生成流水线，全程不读基准自带的任务集；报告的 10 个应用里 Gmail 完全没有合成对应，演化期一次都没见过；演化期用大模型评委、测试期用确定性判分，奖励来源换了；反作弊做了两阶段（先做接地静态分析——反混淆 JS、追踪被评分字段的污点、检测越权访问，再交给独立模型按同一套标准复判，分歧留人工）；口径对自己不利——只有作者自己的轨迹过审计，判为非法的成功一律记失败，公开榜数字照发不做等价筛查。

**跨基准迁移：** Terminal-Bench 上演化出来的 harness 原封不动去跑 SWE-bench Verified，得 84.2%（421/500），比参考 harness 的 80.8% 高 3.4 分，且从未收到 SWE-bench 的任何反馈。

**消融告诉了我们什么：** 新增的 7 个 skill 全部属于同一族——校验与产物契约（推导任务的验收条件、收尾前检查产物、把输出锚定在真实工具执行结果上而不是模型自己的断言）。作者强调：没有一个是加领域知识的。被打开的难点是流程性的（长依赖安装、环境配置、输出校验、多步工具调用），不是知识性的。

## 别被结果骗了：几个要留意的地方

原报告的批评意见，翻成大白话：

**43.5% 这个起点本身可疑。** base Monet 在 Elation 处方上只有 20.0%、Gmail 25.0%，而同一个底座的 Browser Use 分别是 90.8% 和 85.0%。原因是 base Monet 本来是个编码 agent，被临时接到浏览器上，明显没适配，很多失败是撞上防作弊规则后无路可走（审计显示 base 有 14.3% 的尝试是被拦下的）。所以那 49.5 分里，有多少是「进化」、有多少只是「把一个明显没适配的 harness 补到及格」，原文没有拆开。更公允的同模型对照是 86.1% → 93.0%，也就是 6.9 分——量级跟 Terminal-Bench 的 7.7 分差不多。

**进化出来的一部分本事是「更贴着规则边界走」。** 演化后的提示词把「绝对不许直接写状态」放宽成「有界情况下可以调应用自己的 action helper」，而合法性标准恰好把「应用自定义的语义 mutator」列为合法。这不是作弊，但它意味着系统在优化的一部分内容是贴边行走，而这条边是同一批作者划的。残留的 17 条非法轨迹全是原始状态篡改，正好落在这条线的另一侧——说明系统确实在反复试探这条线。

**skill 高度贴合「判分程序检查什么」。** 真实任务的判分程序检查的是被评分字段的最终状态，而进化出来的 skill 正好就是「推导契约 → 校验最终状态与持久化」。这在语义上是正当能力，但也是对判分方式的定向拟合。一旦判分改成检查过程而不是终态，这套 skill 的收益还剩多少，原文没有给证据。

**83.2% 应该读作同域上界，不是泛化能力。** Terminal-Bench 是在同一批 89 个任务上演化然后直接提交榜单。作者的防守是「循环不读参考解」，这挡住了答案泄漏，但挡不住对这 89 个任务分布的过拟合。TerminalWorld 那个 31.7 分的差距，恰好说明这种过拟合在本方法里真实存在，而且很大。

**档案和重组的净贡献没有被证明。** WebArena-Infinity 那次 run 里，重组被反复尝试，但**每一次合并都被回滚了**——也就是说该基准上全部涨幅其实是单血统变异拿到的。TerminalWorld 的合并有效，但附录里又自曝：一个没经过该基准搜索的参考 harness 也能拿到 28/41。作者自己因此把结论缩到「多样档案加保守选择能恢复出一个打败所有现成 agent 的 harness」，而不是「这套搜索能抬高任意起点」。

**统计功效弱。** TerminalWorld 只有 41 个 held-out 任务，多解一个就动 2.4 分。同模型对比（25/41 对 28/41）的 McNemar 检验 p = 0.45，只能算提示性证据。原报告还指出报告里两个 p 值对的是不同对比，并列时容易误读。

**审计不是沙箱。** 静态分析加模型复判比关键词匹配强得多，但不是形式化隔离；高度动态构造的情况可能需要人工复核，且少量轨迹拿不到。

**迁移只测了一个方向**，而且 84.2% 落在 80.8%–84.2% 这个很窄的带里，所以迁移增益远小于同域增益。

另外，两个关键超参数——回退容忍度和探索概率——原文只给了符号，**没给具体数值**。Terminal-Bench 和 TerminalWorld 的代数与总预算也没给。

## 如果我要用这个思路

1. **把准入拆成两道门。** 宽门（有净增益、回退总量小、低采样次数）决定候选能否进档案；严门（全量重测加一遍老任务复查）决定它能否成为后代父本、能否写进最终结论。只有一道门的话：松了会积累噪声胜利，严了会在互补变体出现前把血统冻死。
2. **回退量用求和，别用取最大。** 「单项最多掉 5 分」会放过一大批每项都只掉一点、总量却很难看的改动。
3. **按任务当前状态挑证据来源，别用固定的反思模板。** 一次都没成功过的任务，拿一个更强的参考解法的成功轨迹来蒸馏；同一批采样里有成功也有失败的任务，拿自己的成功与失败轨迹做对比；其余用失败诊断。三种证据最后都翻译成同一种「改 harness」的编辑动作。
4. **把失败模式做全局聚合，再喂给提改动的那一环。** 单条失败诊断只会生成逐任务补丁；聚合出的主导主题（比如「环境安装耗时主导了超时」）才会催生通用能力（「做一个高效安装能力」）。共享记忆同时给提改动的和判准入的两方，两边对「系统性瓶颈是什么」的判断才一致。
5. **别只看训练期的代理分数，保留多个高分变体。** 训练子集饱和到满分而 held-out 只有 68.3%，最贴合代理分数的变体不是泛化最好的。最后用 held-out 去挑或者去合并它们——本文的 28/41 就是合并 4 个专家得到的，超过任何单个（24/25/26/27）。
6. **在能作弊的动作空间里，把合法性做成和能力并列的评分维度。** 先写死标准（哪些信息来源合法、哪些状态修改路径合法），再上静态分析加独立模型复判加人工兜底，报告口径把非法的成功记为失败。

## 名词小词典

| 术语 | 大白话解释 |
| --- | --- |
| harness | agent 的外壳：提示词、skill 文档、工具、控制流。模型是发动机，这是驾驶舱 |
| skill 层 / code 层 | 外壳的两半：写给模型看的文字，和真正执行的代码 |
| 单血统 keep-best | 只维护一个当前最优版本，一路往下改。容易钻死胡同且回不了头 |
| 档案（archive） | 保留所有被打过分的变体的家谱树，包括当时看起来更差的那些 |
| preserve-and-extend 契约 | 准入规则：必须解决新任务，且弄坏老任务的总量在小容忍范围内 |
| fitness | 变体的成绩，来自基准自带的自动判分程序，逐任务通过率取平均 |
| 老任务复查（preservation probe） | 拿这条血统原本已解决的任务重新抽样验一遍，防止悄悄退化 |
| 血统重组（merge） | 把两条解不同任务的血统的改动合起来，合并结果必须覆盖双方全部胜利 |
| stepping stone | 自己没赢、但手里可能握着关键改动的变体，所以也留档 |
| 代理指标过拟合 | 训练期的分数一路饱和，换到没见过的任务上掉一大截 |
| audit-clean | 审计后的通过率：判定为非法作弊的成功一律记为失败 |
