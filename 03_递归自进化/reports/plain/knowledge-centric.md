# 通俗版 · Knowledge-Centric：该留下来的是知识库，还是 agent 本身

> 让 agent 用完就扔，只把带证据的知识条目攒成一个库。

## 一分钟版本

- 主流做法是「让 agent 变强」：改 prompt、改 skill、改 harness、甚至让它改自己的代码。这篇论文说这条路错了方向。
- 它的做法：agent 每次都是全新的、通用的、无记忆的，做完任务就丢。唯一持久的东西是一个共享知识库。
- 知识不是随手记的笔记，是有格式的条目：什么情况下成立、什么情况下不成立、证据是哪次尝试的哪句话、置信度多少。
- 效果不小：ARC-AGI-1 86.7%，成本 `$76`；同预算下 DGM 在 SWE-bench Pro 是 54% / `$713`，它是 64% / `$208`。
- 但它对 skill 路线的三条核心指控（维护贵、难迁移、新改动伤旧任务），一条都没有实际测量过。它只测了解题率和钱。

## 它在质疑什么

先把这个质疑讲到最狠的版本，因为它确实戳得到人。

日常类比：一个老员工干了五年，攒了一身手感——哪个客户不能周五打电话，某个上古系统重启前要先关哪个服务。这些经验全在他脑子里和他的个人工作习惯里。他一走，全没了，新人从零开始。反过来，如果这些经验写进团队文档库，每条写清「适用于什么情况」「什么情况下别照做」「这条是哪次事故总结出来的」，那换谁来都能用，换个部门也能用。

论文说：改 prompt、改 skill、改 agent 代码，就是第一种。收益长在那个特定 agent 身上。具体是三种绑死。

**绑死在特定 agent 设计上。** 你演化出来的一段 skill，引用了具体的工具名、文件路径、上下文格式。换个 harness 就得重写。它不是一条独立的知识，它是那个 harness 的零件。

**绑死在任务分布上。** 一个 prompt 必须对池子里所有任务同时成立，所以优化压力天然把它推向「平均化」——推向那种谁都不得罪、也谁都帮不上的措辞。这是这篇论文最锋利的一刀：**skill 文件里没有地方写「不适用条件」**。

想一下这个场景。你的 skill 里有一条「遇到调度类任务，先建约束图」。后来发现某类调度任务这么干反而更慢，该写「先跑贪心，别过早上图结构」。这两条同时存在就是互相打脸，你只能覆盖掉一条，覆盖就是丢信息。再想一个更疼的：你花了三代演化，终于确认「假设 A 在参数化 B 下是错的」。这条否证信息该写哪？skill 文件是命令式的，全是「做 X」，没有「别做 X，因为我们试过了」的自然位置。所以它通常被直接扔掉，结果第 4 代的 agent 又去踩同一个坑。

**绑死在那一次演化过程上。** 你的 skill 是针对某个 base model 的失败模式调出来的。换个模型，可能白干。

论文顺着这三条往下推，得出的结论是：agent-centric 路线面对的不是性能问题，是维护问题。

- 演化出来的 skill 是「已编译产物」。为什么这么写、依据哪次失败、在什么条件下成立——这些元信息在演化过程中被丢掉了。
- 审查不了就删不掉。skill 库只能单向变长。删一条可能悄悄搞坏三个任务，没人敢动。
- 没有回归门禁。第 N 次改进的净收益可能是负的，而你察觉不到。
- 产出物不可分割。DGM 那类系统吐给你一个 agent，你要么整体接受要么整体拒绝。知识库吐给你一堆条目，可以逐条挑、逐条删。skill 库在中间：文件级可分割，文件内部还是整块。

论文的一句话总结：**你该演化的不是「怎么做」的指令，而是「什么成立」的命题。前者天生绑载体，后者天生可搬。**

## 它的替代方案怎么运作

想象一个咨询公司，但规则很怪：每个项目都派全新的顾问，没有老手，谁也不许留私人笔记本。项目做完，顾问必须把心得发到公司内网论坛，发帖有硬门槛——你没先搜过库里已有的帖子，系统直接拒收。每条心得必须点名具体的东西（某个 API、某个文件路径、某个错误类型），写「要更仔细地读题」这种话会被判为废话丢掉。

然后是论坛环节。别人发的帖你必须表态：同意、反对、或者综合。反对的时候必须给证据——引用具体哪个任务的哪次尝试。最后有个「资料员」把活下来的帖子压缩成一份简报，明天的新顾问上工前先读它。

论文的三段协议就是这个：做题 → 单任务论坛 → 跨任务论坛 → 蒸馏成简报。跑 10 代，每代 50 个任务。一个虚构的知识条目大概长这样：

```
text: 当测试报 UnicodeDecodeError 且文件来自 tar 包解压时，先用二进制模式读首 4 字节判断 BOM
applies_when: 输入文件路径来自 tarfile.extractall
does_not_apply_when: 文件由测试自己在 tmpdir 里写出（此时编码已由测试固定）
evidence:
  - task_id: py__csv_parse
    post_id: 412
    quote: "assert 失败在第 3 行，实际读到 '\ufeffid'，说明 BOM 未被剥离"
confidence: high
rejected_hypotheses:
  - FALSIFIED: 用 errors='ignore' 绕过 —— 会静默吞掉正文里的非 ASCII 字符（task py__csv_parse 第 2 代实测失败）
    UNTRIED: 显式指定 encoding='utf-8-sig'
```

注意三个 skill 文件写不出来的东西：作用域（applies_when / does_not_apply_when）、证据链（能溯源到具体那一次尝试的那一句话）、被否证的具体参数化（不是「这个方向死了」，而是「这一种写法死了，那一种还没试」）。

论文里最有说服力的例子正是第三点。一道 ARC 题，第一代有个 agent 因为一次失败就把整个「标记控制几何变换」的思路一刀切否掉。第二轮有人引用同代已经解出的另一道题作反例，反对他。资料员的处理不是选边站，而是把否证**收窄**成「只有『标记在矩形上方则矩形不变』这一种写法被证伪，其他四种还没试」。第二代的新 agent 拿到这个，把题解出来了。如果第一代那个「整族都死了」的结论被当成共识收下，这道题永远解不出。

还有一个反直觉的设计：有道六边形棋盘的题，十代都没解出来，两派人争了十代。知识库的处理是**把两派都留着**，各自标上支持和反对的证据，不强行取共识。论文管这叫预期行为——证据真冲突的时候，协议的活是把冲突留得清清楚楚，不是把它抹平。

## 它拿出了什么证据

五个 benchmark，每个 50 道题（终端那个是 89 道全量），跑 10 代，3 个随机种子。

**对比会自己改代码的 agent（Haiku 4.5 底座）：**

| | 它 | HyperAgents | DGM |
|---|---|---|---|
| ARC-AGI-1 | 86.7% / `$76` | 70% / `$234` | — |
| ARC-AGI-2 | 82.7% / `$80` | 60% / `$188` | — |
| Polyglot | 68.0% / `$126` | 52% / `$190` | 58% / `$281` |
| SWE-bench Pro | 64.0% / `$208` | 42% / `$431` | 54% / `$713` |

最扎眼的是 SWE-bench Pro 那行：解题率高 10 个点，钱只花了 `$208` 对 `$713`。成本口径是含对手 meta-loop 自改代码的 token 的，所以这个差距不太可能是算法口径造成的。

**对比 prompt 优化器（预算对齐）：** GEPA 在 ARC-AGI-1 做到 44%，Polyglot 36%；OpenEvolve 分别 54% 和 46%。它是 86.7% 和 68.0%。差距很大，但注意 OpenEvolve 在这里是被当 system prompt 演化器用的，不是它的全部能力。

**换模型：** 换成 GPT-5.4-mini 后四个 benchmark 全面更好也更便宜：Polyglot 72.7% / `$56`，SWE-bench Pro 70.7% / `$157`，ARC-AGI-1 93.3% / `$16`，ARC-AGI-2 90.0% / `$20`。ARC 上成本差了近 5 倍（`$16` vs `$76`），论文没解释为什么。

**知识能不能搬走（核心卖点）：** 用一个模型攒出知识库，冻结，交给另一个模型去做**没见过的新题**。新模型不许再论坛、不许再蒸馏，只是把冻结的知识当参考资料读一遍。

ARC-AGI-1（20 道新题）：GPT 从 23.3% 涨到 43.3%（吃 GPT 攒的知识）、38.3%（吃 Haiku 攒的知识）；Haiku 从 13.3% 涨到 28.3% / 23.3%。Polyglot：GPT 从 8.3% 涨到 20.0% / 11.7%；Haiku 从 3.3% 涨到 11.7% / 11.7%。八个组合全是正增益，跨模型家族双向都正。

**哪些只是案例展示，不是证据：** 「知识库可审查」这条只有定性展示——给你看了几段真实的知识库文本，加一个论坛立场的关键词统计。没有人工审查实验，没有验证过「人真的能靠这个删掉错知识」。上面那三个精彩案例也是存在性证明（这机制确实发生过），不是贡献度证明（它贡献了多少个点）。

## 这个质疑站得住吗：几处硬伤

这一节是全文重点。上面那些漂亮数字都不假，问题在于**它们测的不是它指控的东西**。

**硬伤一：三条核心指控一条都没测。**

它指控 agent-centric 路线维护成本高、难迁移、新适配伤旧任务。它测的是什么？解题率和美元开销。

维护成本没测（那个成本表算的是跑一次花的钱，不是养一套系统花的人力，论文措辞里这两个混着用了）。迁移衰减没测——它没做「把 DGM 演化出来的 agent 搬到另一个 benchmark 或另一个模型上，看还剩多少收益」这个实验，而这才是「难迁移」这条指控的对称验证。「新适配伤旧任务」也没测。所以第一节那些批评在论文里的地位是：**有说服力的机制推理 + 间接的性能数字，不是被验证的实证结论。**

**硬伤二（最关键）：它用实验设置绕开了那个缺陷，而不是解决了它。**

论文的协议里有一条规则：已经解出的任务从活跃池里移除，后面不再花 token 重跑。停下来想一秒这意味着什么。

它指控对手路线的主要毛病是「每次新适配可能损害之前学会的任务」。而它自己的实验协议规定：**学会的任务不再被评测。** 那当然不会退化——你根本没在看。

真要验证单调性，需要的实验是：拿第 10 代的知识库，回去重做第 1 代已经解出的任务，看解题率有没有掉。这个实验论文没做。我不认为这是刻意的，但结论是明确的：**知识库的「不遗忘」优势在这篇论文里是被设置保证的，不是被验证的。**

顺带说，这也让 86.7% 这个数字需要看清口径——它是「10 代里任意一代解出」的累积通过率，接近 pass@10，不是单次通过率。DGM/HyperAgents 的重跑是同样预算，这部分可比；但终端那个 43.8% vs 37.6% 是拿别人论文里各系统自报的分数比的，对手有没有同样 10 次尝试的预算，论文没说明。那 6.2 个点在这种情况下不能当方法优越性的证据。

**硬伤三：唯一针对可迁移性的实验有两个问题。**

先说样本量：每格 20 道题 × 3 个种子。ARC 上 Haiku 从 13.3% 到 23.3%，绝对值是 20 道题里多解 2 道。Polyglot 上 Haiku 从 3.3% 到 11.7%，是从 0.67 道到 2.3 道。方向可信，量级别当真。

问题一，**同题泄漏，作者自己披露的**：Polyglot 那 20 道测试题里，有 7 道是知识来源题的同一个 Exercism 练习换了另一种语言写（比如来源是 `go__ledger`，测试题是 `java__ledger`）。7/20 = 35%，而绝对增益只有 1 到 2 道题的量级。也就是说，**Polyglot 的迁移结论几乎排除不掉「就是背了同一道题」这个解释。** ARC 那半张表没这个结构，所以只有 ARC 那半张才是真的迁移证据。

问题二，**缺公平对照**：迁移的时候多加了一个部件——一个「适配器」，它读当前任务和知识库，挑出 0 到 3 条相关的写成备忘。这是一次额外的 LLM 调用，而且它看得到任务描述。对照组（无知识）不走这个适配器，实验组走。

所以你分不清收益是来自「知识」还是来自「多做了一次任务分析」。缺的对照组很简单也很明显：**空知识库，同样走一遍适配器。** 论文没做。这是迁移实验最大的方法论漏洞。

**硬伤四：花大段论证优于同类系统，实验里一个这类基线都没有。**

论文第 2 节用很长篇幅论证自己比 ExpeL、Agent Workflow Memory、AgentKB、Voyager、Mem0 这类「存自己的成功失败经验」的系统更好——它们是 agent 自己压缩自己的轨迹，而这篇是多方带证据地互相裁决。实验里这类基线：零个。

最自然的对照组不是 DGM，而是「同样冻结 agent、同样往 MEMORY.md 里注入经验，但只做单 agent 自我总结，不做论坛论辩」。没有这个对照，我们无法区分收益来自「知识外置」还是来自「多 agent 论辩式策展」。

**整篇论文最独特的机制（论坛 + 强制表态 + 否证收窄），恰恰是唯一没被消融的部分。** 协议内部也是零消融：为什么是 1 轮单任务论坛 + 2 轮跨任务论坛？去掉跨任务论坛掉几个点？去掉「已否证假设」字段掉几个点？去掉服务端的检索门禁掉几个点？全部没有。

**硬伤五：一个反讽的数据。**

论坛帖子的立场统计（Haiku 那批，1354 条第二轮及以后的帖）：同意 512 条，综合 861 条，反对只有 73 条。反对占 5.4%。而论文里最精彩的三个案例——引用已解任务打掉过度泛化、作者自己推翻自己、两派分歧被完整保留——全部来自反对这条通路。

**产出价值最高的那条通路，使用频率最低。** 论文没讨论怎么提高它。作者的解释是「强制表态让冲突显性化并携带证据，它不制造冲突」，这话没错，但 64% 的帖子选「综合」是个信号：模型的默认行为是把两方的话缝在一起，而缝合恰好是最容易生成看起来兼容、实际上丢了作用域的泛化 claim 的动作。另外，GPT-5.4-mini 那批 run「用自由文本表达对立，不吐这些关键词」，所以统计只能限于 Haiku——**协议的结构化程度本身是模型依赖的。**

**硬伤六：这套协议本身就是一个 harness。**

服务端门禁、schema 校验、两类论坛的轮数、蒸馏器的取舍规则、迁移适配器的 prompt、prompt cache 的前后缀切分——这些全是人工设计并针对 benchmark 调过的工程结构。论文说 agent 是通用且一次性的，在「做题的那个 agent」这个意义上这话成立；但整条策展流水线是一套相当复杂、不可丢弃的持久基础设施。维护成本没有消失，它从 agent 搬到了协议。论文没论证这个搬迁是否更划算——而这恰恰是「更便宜维护」这个主张最需要论证的地方。

还有一点：作者选 benchmark 的理由自己就透露了适用边界。他们说 ARC 适合研究知识策展，因为「变换规则离散可验证，很多规则在不同任务里反复出现」；Polyglot 适合是因为「复发失败模式和语言惯用法在任务间稳定浮现」。共同点是**任务间存在强复发结构**。知识策展的收益上限直接取决于任务里可复用命题的密度，而三类任务恰好都是高密度的。低复发、强异质的任务流上还剩多少收益，没测。

## 我的判断：要不要改主意

我的立场：**这个质疑有一半是硬的，你该按那一半改设计；另一半只是断言，可以先放下。不需要改路线。**

先说该接受的部分。这几条不需要论文提供实验，靠机制推理就成立，而且它们在指出你系统里的真实缺陷：

**载体表达力这条完全成立。** skill 文件是命令式的，装不了「不适用条件」和「已被否证的具体参数化」。这不是实现问题，是形式问题。你现在每一轮演化都在丢掉否证信息，后续的 agent 会反复踩同一个坑。这条必须改。

**证据链这条完全成立。** 你 skill 里的每条指令，如果溯源不到一次具体的、有验证器结果的尝试，你就没有删除的依据。没有删除依据，skill 库只能单向膨胀。膨胀和稀释是同一件事的两面。

**回归门禁这条成立，而且讽刺的是论文自己也没做。** 「新适配伤旧任务」是真风险。论文用「已解任务出池」绕开了它，你绕不开。但这条恰好说明：这不是 skill 路线独有的病，是所有自改进系统共有的病，只是论文的设置让它看不见。你该做的不是放弃 skill，是加一个回归集。

**第二方带证据的挑战这条成立。** 单 agent 自我总结的错误率没有任何上界。论文最强的三个案例全都依赖第二方拿证据反驳，单 agent 自省结构上产生不出来。

再说可以先放下的部分：

**「维护成本高」目前只是断言。** 它没测过，你也没必要因为一句没测过的话推翻自己的设计。反过来，它自己那套策展流水线的维护成本也没测，凭什么说更便宜。**「难迁移」的证据只有半张表撑着**——ARC 那半张是真的，Polyglot 那半张有 35% 的同题泄漏，而且整个迁移实验缺一个「空知识库走适配器」的对照，这个结论目前是指示性的，不是判决。**「知识库比 skill 强」在实验上没被证明过**，因为它连一个「冻结 agent + 朴素经验注入」的基线都没有。

**互斥还是可叠加：可叠加。而且论文自己就是这么说的**——它在摘要和第一节都用的是 complementary（互补），不是 alternative（替代），结论节还把「研究知识中心与 agent 中心的协同」列为后续方向。两者改的是不同的东西：

- skill 演化改的是**动作空间**——agent 能做什么、按什么顺序做。
- 知识策展改的是**信念状态**——关于这个任务域，什么为真、什么已被否证、在什么条件下。

这两层的更新节奏完全不同。动作空间的更新应该少而慎，每次都改变行为，风险高，需要回归测试。信念状态的更新可以多而细，单条错误的影响可以被其他条目和硬验证器冲抵。**现在多数 skill 自进化系统的病根，就是把高频、细粒度、带条件的信念更新，硬压进低频、粗粒度、无条件的动作载体。** 于是你只能在「不更新」和「污染 skill」之间选。

所以具体怎么办：给两层各自的更新通道。可执行、可测试、稳定复用的东西（脚本、命令序列、工具封装）继续沉淀成 skill，保持稳定并过回归测试。关于任务域的经验性命题（哪类失败在复发、哪个假设已被否证、哪个不变量成立）沉淀成带作用域和证据的知识条目，允许高频写入、允许被后续证据打掉。不是换路线，是加一层。

顺便一个论文没说但工程上很实际的取舍：两条路线的失效方式不一样。skill 的失效是突变式的——工具升级、API 改名，一整批同时失效，而且往往静默失效（还能跑，只是行为错了）。知识条目的失效是渐变式的——某条命题不再成立时硬验证器会给出反证，最多被降权或标成已否证，不会让 agent 直接执行错误动作。代价是 agent 每次都要重新推导执行细节，更贵、更慢、方差更大。论文的成本表看起来推翻了这个代价，但它的对照组是会跑 meta-loop 的重系统，不是「一个手写好 skill 的精简 agent」——后者才是你真正的竞争者，论文没这个基线。

## 如果我在做 skill 自进化，这篇迫使我回答三个问题

写进设计文档，逐条给答案：

1. **我的载体能表达作用域和否证吗？** 具体点：能不能写「这条只在 X 条件下成立」，以及「假设 A 在参数化 B 下已被证伪，但参数化 C、D 还没试」？如果不能，我每次演化都在丢弃否证信息。
2. **我 skill 里的每条指令能溯源到一次带验证器结果的具体尝试吗？** 如果不能，我没有删除的依据，库只能单向膨胀。
3. **我有回归门禁吗？** 第 10 代的产物回测第 1 代已解的任务，解题率保持吗？论文用「已解任务出池」绕过了这个问题，我绕不过。这是我必须自己建的东西。
4. **我的知识提炼是单 agent 自省，还是有第二方带证据的挑战？** 前者的错误率没有上界。如果我只有单 agent 自省，我应该至少加一条「引用一个已解任务作反例」的强制路径。
5. **我的 skill 换个 base model、换个 harness，还剩多少收益？** 如果没测过，我不知道自己是在积累资产还是在积累负债。这个实验论文也没对 DGM 做，但我可以对自己做。

再补一条实操：如果我要加知识层，入库门禁必须做到服务端，不能只写在 prompt 里。论文的做法是——agent 没先检索过知识库，服务端直接拒收它的写入；引用了不存在的任务 id，直接拒。写在 prompt 里的门禁等于没有门禁。

## 名词小词典

| 术语 | 大白话解释 |
|---|---|
| agent-centric | 「让 agent 变强」派。改进落在 prompt、skill、harness、agent 代码上 |
| knowledge-centric | 「让知识库变强」派。agent 用完就扔，只有知识库持久 |
| harness | 包在模型外面的那层脚手架：工具接口、循环控制、上下文拼装 |
| skill | 一份告诉 agent「该怎么做」的说明文件，本质是可执行指令文本 |
| insight / 知识条目 | 一条「什么成立」的命题，带适用条件、不适用条件、证据、置信度 |
| forum / 论坛 | agent 之间互相发帖、引用证据、表态支持或反驳的环节 |
| distillation / 蒸馏 | 把活下来的帖子挑选压缩成下一代能直接读的简报。是挑选，不是摘要 |
| FALSIFIED / UNTRIED | 「这一种写法试过了，错的」/「这几种还没试」。用来防止把一整族思路误杀 |
| 硬验证器 | 机器判对错的东西：精确匹配、测试套件、容器里跑通。不是让模型自己打分 |
| 消融实验 | 拆掉系统的某个零件，看性能掉多少，用来证明这个零件真的有用 |
| pass@N | 允许尝试 N 次，任意一次成功就算过。这篇的解题率接近 pass@10 |
| 同题泄漏 | 测试题和训练题其实是同一道，只是换了个形式。会让迁移效果虚高 |
