# 通俗版 · AutoDesign：让 agent 自己改进「怎么做海报」

> 不训模型，只让 AI 反复重写自己的工作流代码，把论文自动做成海报。

## 一分钟版本

- 模型权重全程不动。改的是模型外面那一圈东西：提示词、工具、渲染流程、检查器、重试策略。论文把这一圈叫 harness（外壳）。
- 有两个角色。一个「元优化器」看试跑记录、找反复出现的毛病、写改造计划；一个「代码 agent」按计划真的去改外壳的代码。改完跑一遍，分数涨了才留下。
- 落地任务是「论文 → 学术海报」。有一套自己造的评测叫 PosterBench，100 篇论文，七个维度打分，总分 100。
- 主结果：78.32 分，比同配置最强对比系统高 7.45 分。挂上这套外壳能让弱模型平均涨 12.40 个绝对分。
- 但有三个坑：系统在没被重点计分的维度上退化了；用来校准的人工评分噪声极大；纯自主演化会卡住，靠人指方向才突破。

## 它想解决什么问题

想象你要写一个「论文自动转海报」的工具。你会写一堆东西：怎么解析 PDF、怎么抽图表、排三列还是两列、字号多大、发现文字溢出了怎么补救、什么时候算做完了。

这些东西一旦写死，就固定了。下次遇到一篇图特别多的论文，它还是按老套路排，排烂了也不会变聪明。

现有的做法只能改「这一次的产出」。比如让模型自己看一眼海报，发现字挤了就改一下这张海报。下一篇论文来了，同样的错还会犯一次。论文的说法是：这些系统把人给的反馈当成一次性的信号，而不是可复用的设计知识。

AutoDesign 想改的是工具本身。海报排烂了，不只是修这张海报，而是去改「排版模块的代码」，让以后所有海报都不再犯这个错。这就是它说的「把设计能力变成生产系统的持久能力」。

## 核心思路

类比：一家开了很久的小餐馆。

- 厨师是模型，手艺不变（权重冻结）。
- 厨房的动线、菜谱卡、锅具、出菜前的检查单，是 harness。
- 店长是元优化器。他不炒菜，他看这一周的客人反馈和废菜记录，得出结论「问题出在备菜台太窄」。
- 装修师傅是代码 agent。店长说改备菜台，他就去动那一块。
- 改完试营业一周，评分涨了才保留，不涨就拆回去。

论文把外壳明确切成五块：上下文与记忆、工具与规范、执行运行时、编排调度、评估与反馈。**每一轮只准改其中一块。** 好处很实在：这一轮分数涨了跌了，你知道是哪块造成的。代价是跨模块的联动改进做不了。

它还有一个刻意的限制：同一时刻只有一个「当前外壳」，不搞多个变体并行进化、择优保留那种树搜索。这是它和 Darwin Gödel Machine 那类开放式演化的主要区别。

规模上：7 天演化，调用 224 个 subagent，至少 123 次迭代，最终累积 54 次外壳更新。跑一张成品海报大概 253 次工具调用、11 轮编辑、40 分钟、成本不到 3 美元。

### 「对齐人类设计先验」其实是什么

这个词听起来很玄，拆开看就三件很土的事：

1. 人先手工标注了一批参考海报，按七个维度给分。评分器是照着这批参考实现出来的。
2. 一份非常长的手写提示词，里面全是硬规矩：海报 3072×1536、2:1、三列、7 到 10 个编号小节、页头只允许标题/作者/机构三行、不许放 logo 和二维码、不许搞 KPI 大数字条、表格必须用原始 PDF 截图不许重画、必须用 Times 这类衬线体、表格不许画竖线、配色最多一个主强调色加一个次强调色。甚至规定了 HTML 结构要长什么样。
3. 评分权重本身：把「可读性最重要」写进了分数。

第 2 条要特别注意：这份提示词是**所有对比系统共用的**。所以这些人类设计规则不是 AutoDesign 独家的优势。但反过来说，「对齐人类设计先验」里有相当大一块其实是人手工调提示词，不是系统自己学出来的。另外这份共享提示词里含有明显是给 AutoDesign 自家校验器准备的 HTML 结构约定，把它塞给对比系统是否公平，论文没讨论。

## 怎么打分：这是最关键也最容易出问题的地方

自己改自己、又自己给自己打分，等于让学生自己出卷自己批。分数一定会涨，但涨的可能只是「会考试」。所以打分设计是这篇最该被仔细看的部分。

分数由七个维度加权组成，总分 100：

| 维度 | 权重 | 怎么打 |
| --- | --- | --- |
| 忠实度 Faithfulness | 10 | 程序 + 模型判断 |
| 覆盖度 Coverage | 10 | 纯模型判断 |
| 信息密度 Density | 15 | 纯程序 |
| 视觉证据 Visual Evidence | 10 | 程序 + 模型判断 |
| 版面 Layout | 20 | 纯程序 |
| 可读性 Readability | 25 | 程序 + 模型判断 |
| 美观度 Aesthetics | 10 | 纯模型判断 |

关键点：**权重最高的版面(20) 和信息密度(15) 是纯程序算的**——量渲染尺寸、OCR 出文字覆盖了多少面积、检测有没有重叠和裁切。纯靠模型主观判断的只有覆盖度和美观度，加起来 20 分。这是这套协议可信度的主要来源。

另外还有一层「封顶」机制：如果版面严重损坏、或者出现已确认的可见失败，总分会被强行压到一个上限，比如 40 分。因为是先封顶再取平均，所以你拿表格里各维度的平均分加权算，是**算不出总分**的，论文自己也说明了这点。

作者为了防止自己骗自己，做了三级隔离，这一点比同类工作扎实：

1. **优化期评分器**：演化过程中用的评分器，在整个 run 里冻结，不许改。
2. **验收闸门**：改动要被接受，必须训练集分数上升，且一个独立开发集分数不下降。而开发集的结果**从来不给元优化器看**——它只知道通过了还是没通过，不知道具体错在哪。这相当于期末考的卷子不给你看,只告诉你及格没及格。
3. **最终评测**：对外报的分用完全冻结的 PosterBench，加上一次系统全盲的人工两两比较。这两个都在演化循环之外，系统碰不到。

给模型判分时还屏蔽了系统身份和生成提示词，判分记录也全部公开可审计。这些都是该抄的做法。

但隔离并不彻底。作者自己在附录里承认：PosterBench 的七个维度和优化期评分器**用的是同一套质量词汇**，而且两者都是「程序检查 + 模型判断」的组合。词汇同源、信号来源同源，意味着在优化期评分器上刷分，天然就会在 PosterBench 上涨分——这两个分数不是统计独立的。更麻烦的是，优化期评分器本身也是一个代码 agent 写出来的。论文没有给出这两个评分器分数之间的相关性分析。

## 跑出来的效果

主赛道，100 篇论文：

- AutoDesign（Claude Code + Claude 4.8）**78.32**，全表最高。同配置的 Claude Design 70.87，差 7.45 分。OpenDesign 69.45，差 8.87 分。
- 换成 Codex + GPT-5.5 是 77.97，基本持平。
- 什么外壳都不挂的裸代码 agent：Codex/GPT-5.5 是 73.37，Claude Code/Claude 4.8 是 70.01（挂上外壳 +8.31 到 78.32）。
- 人工手写的老工作流明显偏低：PosterGen 56.71、Any2Poster 49.09、Paper2Poster 44.61。

七个受控配置（固定模型和代码 agent，只切换有没有这套外壳，10 篇 mini 集）：均值从 54.99 涨到 67.39，单个配置增益从 5.01 到 19.56 分。规律很干净：**基座模型越弱，外壳收益越大**。DeepSeek V4 Pro 从 34.73 涨到 54.29（+19.56），而 GPT-5.5 只从 75.87 到 81.46（+5.59）。含义是这套外壳主要在补弱模型的执行力和自检能力，强模型本来就会做，补不了多少。

作者给的机制解释挺有说服力：每一轮都把上一轮渲染出来的图当视觉上下文喂回去。纯文字诊断说不清「这里裁切了」，看一眼图就知道。

成本上，Pareto 前沿是 LongCat 2.0（55.13 分，每张 0.27 美元）→ Doubao Seed 2.1 Pro（71.83，2.75 美元）→ Claude 4.8（74.56，7.63 美元）→ GPT-5.5（81.46，10.02 美元）。Doubao 用 27% 的成本拿到 GPT-5.5 的 88% 分数。注意 LongCat 那个 0.27 美元靠的是评测时缓存命中不计费。

人评：AutoDesign 的胜率点估计 64.0%，高于裸 Claude Code 51.7、OpenDesign 43.4、Claude Design 40.9。

顺手说一处口径错误：摘要把「平均涨了 12.40 个绝对分」写成了「+12.4%」。百分号用错了。按分数算相对增幅其实约 22.6%。不影响结论，但会误导读者。

## 别被结果骗了：三个要留意的地方

### 一、Goodhart 效应已经出现在主结果表里

Goodhart 效应就是「一旦某个指标被当成目标，它就不再是好指标」。学校按考试成绩排名，学校就开始教应试技巧。

这事在主结果表里已经能看到了。AutoDesign 的**视觉证据只有 5.97、美观度只有 5.59**，都**低于**对比系统 Claude Design（7.62 / 7.36），甚至低于什么外壳都不挂的裸 Claude Code（7.01 / 6.53）。

它是靠哪两项赢的？信息密度 8.41（对手 6.48 / 5.71）和可读性 8.17（对手 5.96 / 6.68）。而这两项的权重是 15 和 25，加起来 40 分，正好是全表最重的两项。

结论直说：**系统被评分表推着走了。** 它在被重点计分的地方拼命优化，在没被重点计分的地方退化了——退化到还不如什么都不做的裸模型。而且退化的那两项，恰好是靠模型主观判断打分的维度。这和演化轨迹图里 plateau 阶段仍然标着「图信息稀疏」的观察是一致的。

这不是理论担忧，这是已经发生的、写在主表里的事实。

### 二、用来验证的人工评分本身噪声很大

作者请了 11 名志愿者，系统全盲，两两比较，收了 936 份响应（933 份有效判定 + 3 份跳过），用 Bradley–Terry 模型拟合，跑了 2000 次 bootstrap。流程规范，值得肯定。

但看数字：

- **评审员之间的一致性系数只有 0.101。** 这个数满分是 1。0.101 意味着不同的人对同一对海报的判断几乎各说各话。
- **人评和自动分的相关性只有 0.34**（95% 置信区间 0.22 到 0.44）。
- 把判定按分差分箱后：两个海报自动分差 0 到 3 分时，自动分和人的偏好一致率只有 **51.9%**——基本等于抛硬币。只有分差 ≥20 分时才升到 74.4%。
- AutoDesign 的胜率点估计 64.0%，但 95% 区间是 **55.2% 到 77.8%**。下界离 50%（也就是「没差别」）只有 5 个点。

作者的解释是「基准不需要复刻人类偏好」，理由是基准评七个维度而盲测只问一次二选一。这个解释站得住。但结论还是要说清楚：**这套基准只在大分差处可信，细粒度上几乎没有分辨力。** 所以「78.32 比 70.87 高」是可信的方向性结论，「涨了 0.5 分算改进」不可信。

前面说三级隔离做得比同类扎实，是真的。但第三级——本该作为独立校准的人评——它自己就抖得厉害。隔离设计好，不等于校准结果可靠。

### 三、纯自主演化会卡住，突破靠人不靠算力

演化轨迹（某一篇代表性论文，不是基准均值，别和 78.32 混着比）：

- 初始外壳 **49.00**
- 自主优化一路涨到 **80.88**，然后卡住不动了
- 人给了一个方向性提示、重定向之后，冲到 **88.39**

作者的原话是这套代码 agent「可能过早收敛到一个局部满意的配置，此时外层优化就停滞了」。它不搞树搜索、只有单条路径，卡在局部最优是可预期的。

**关键是：从 80.88 到 88.39 不是靠多跑几天、多花算力换来的，是靠人给了方向。** 对任何做「自进化 agent」的人，这是一个很硬的数据点——plateau 检测和人工重定向接口应该当成一等设计，不是事后补丁。

而且系统在评估器这一层完全没有自纠能力。论文明说了：优化期评分器保持不动，因为系统拿不到任何外部信号来识别或纠正评分器偏差。只有人肉眼看出海报有系统性偏差，才能触发评分器修订。

还有一件更奇怪的事，藏在受控实验里。三个受控赛道各自的分数跨度是：

- 换**设计外壳**（也就是本文的核心贡献那一层）：74.56 / 70.36 / 66.83，跨度约 **7.7 分**。
- 换**代码 agent 外壳**（就是「谁来写代码」这一层）：Kimi Code 82.31、ZCode 69.53、OpenCode 67.87、Claude Code 64.33，跨度 **17.98 分**，接近 18 分。
- 换**模型**：跨度 20.27 分。

也就是说，在固定其他变量的条件下，**换「写代码的那个外壳」造成的分数波动，比换「设计外壳」大一倍多**。被当作核心贡献的那一层，影响反而是三者里最小的。更刺眼的是 GLM 5.2 配 Kimi Code 拿到 82.31，反超了 Claude 4.8 那套配置的 74.56。

作者只客观陈述了「Kimi Code 得分最高 82.31」，没有解释这意味着什么，也没解释 GLM 5.2 为什么能反超。这是一个应该被解释但没被解释的结果。

## 如果我要用这个思路

1. **把要演化的东西显式切成几块，一轮只改一块。** 五分法（上下文与记忆 / 工具与规范 / 执行运行时 / 编排 / 评估与反馈）可以直接搬。好处不只是可归因——被拒绝的提案也变成了有用信息（「这个方向试过，不行」），而不是噪声。

2. **验收闸门必须用优化器看不见的数据。** 具体就两条：训练集必须严格上升，独立开发集不许下降。工程上要保证开发集的轨迹和分数**一行都不写进**优化器的上下文。这是防过拟合最便宜的措施。

3. **设计评分函数时，反过来想「怎么刷分最省力」。** 这是本文最值得学的一课，因为它自己也没躲过。具体做法：
   - 高权重维度尽量做成程序化的确定性检查（渲染完整性、溢出重叠、OCR 覆盖率、数字和源文件一致），把主观的模型判分压到低权重。
   - **给每个维度设地板，不只设总分。** AutoDesign 的教训就是低权重维度可以自由退化。加一条「任何维度不得低于初始基线」的硬约束，能挡住这类退化。
   - 用「封顶」而不是「扣分」来处理致命问题。分数被压到 40，比扣 10 分有效得多，因为刷高其他维度也补不回来。
   - 定期换一批冻结的参考任务和对抗性探针。作者自己也这么建议：自适应评分器必须有版本、必须被冻结的参考任务锚住、必须有周期性人工审计。

4. **把优化日志做成带代码 checkpoint 的结构化记录。** 每轮存：外壳快照、轨迹和分数、改了哪块、改造计划、代码 diff、接受还是拒绝。这样能回滚、能复现、能避免重复试错。比把历史塞进提示词可靠得多。

5. **内层循环留两个出口。** 一是通过全部阻断性检查就立刻停（论文里最多 12 次尝试）；二是预算烧完就从保留的历史里挑一个还满足底线约束的交付。这避免了「要么死循环要么交废品」。

6. **把 plateau 检测和人工重定向做成一等接口。** 人只给自然语言的观察和方向，不直接改代码。评分器的修订单独走一条必须人工触发的通道。别指望系统自己发现评分器有偏。

7. **让产出物始终是可编辑的代码，上下文只构建一次。** 论文的做法是 ingestion 阶段一次性抽出元数据、大纲、关键段落、图表和回源指针，后面所有修订步骤复用；产物全程是可编辑 HTML，改动落成局部编辑而不是整体重生成。省 token、保留可核查的来源链、最终产物人还能接着改。

## 名词小词典

| 术语 | 大白话解释 |
| --- | --- |
| harness（外壳） | 模型外面那一圈工程代码：提示词、工具、流程、检查器、重试逻辑。模型是发动机，harness 是整辆车 |
| meta-harness optimizer（元优化器） | 看试跑结果、找病根、写改造计划的那个角色。它不写代码，只出方案 |
| rollout（试跑） | 拿当前外壳把一批任务真跑一遍，收集产出和过程记录 |
| acceptance gate（验收闸门） | 改动能不能留下的判定规则：训练集涨、开发集不跌 |
| held-out dev set（独立开发集） | 一批优化器看不到的任务，专门用来检查「是真变好了还是只是背题」 |
| 冻结权重 | 全程不训练、不微调模型。只改模型外面的东西 |
| Goodhart 效应 | 指标一旦变成目标就失效。按考试排名，学校就开始教应试 |
| reward hacking（刷分） | 系统学会了拿高分的捷径，但产出的实际质量没变好甚至变差 |
| plateau（平台期） | 分数涨到某个值就不动了，再跑也没用 |
| VLM judge（模型判分） | 用一个能看图的大模型给产出打主观分，比如「好不好看」 |
| Bradley–Terry | 从一堆两两比较的结果里，反推每个系统的整体胜率 |
| Krippendorff 一致性 | 衡量多个标注员意见有多一致，满分 1。本文只有 0.101，等于各说各话 |
