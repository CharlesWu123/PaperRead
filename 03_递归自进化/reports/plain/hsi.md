# 通俗版 · HSI：一个模型，三层身份

> 模型权重不动，只让它反复改写自己的外壳代码，成绩翻倍。

## 一分钟版本

- 一个冻结的 LLM（DeepSeek-V4-Flash）同时干三件事：执行任务、改写执行任务用的那套外壳代码、改写「该怎么改外壳」这套方法。
- 全程不训练、不微调、不蒸馏、不加 LoRA。变的只有代码，不是模型。
- 第三层（改方法的那层）之上有一个不可修改的锚点，递归到这里硬性截断，没有第四层。
- 在 BALROG 六个文本游戏上，平均分从 18.9 提到 41.4。BabyAI +39.3，Crafter +33.0，TextWorld +25.0，MiniHack +15.0。
- 但摘要吹的「两个理论上界」其实没有定理也没有证明；第三层的增益有预算混淆，而且换一组设置就不成立。

## 它想解决什么问题

你手上有一个模型能力固定的 agent。围着它的那一圈东西——prompt 怎么写、有哪些工具、记忆怎么存、状态怎么跟、失败怎么重试——论文里统称 harness，中文可以叫「外壳」。

外壳对结果的影响非常大。原报告引的 Harness-Bench 数据：同一个模型，最好的外壳和最差的外壳差 23.8 分。

但工程实践里，外壳基本是上线前手写好、上线后就冻在那儿。这很奇怪：影响最大的变量，反而是最不动的那个。

举个具体例子。你写了个玩 Crafter（一个类 Minecraft 的文本游戏）的 agent。上线后你发现模型总是不知道自己背包里有什么，因为你的 prompt 没把 inventory 结构化地喂进去。这个问题模型自己在轨迹里就能看出来——但它没有权限改你的 prompt 模板。HSI 干的事就是：把这个权限给它。

论文还要回答一个更尖锐的质疑。有人（Wang et al. 2026b）做过对照实验：外壳演化 67.4% 对并行采样 72.3%；有单元测试时 75.8% 对 86.0%；在搜索集和评测集不重叠的任务上，泛化增益只有 +0.6pp。意思是：外壳演化的收益可能只是「多花了推理算力」的另一种包装。HSI 必须证明自己不是。

## 核心思路：三层结构

类比：

- **第一层，员工**：按现有工作流干活。这里的「工作流」就是 task harness。
- **第二层，组长**：不干活，只看员工的成绩单，然后改工作流。它叫 evolver。
- **第三层，总监**：不改工作流，只改「组长该怎么改工作流」这套方法论。它叫 meta-evolver。
- **公司章程**：总监的执行逻辑本身从一份不可修改的模板加载，谁都改不了。这就是 frozen outer anchor（冻结外层锚点）。

关键点：这三个不是三个模型，是同一个冻结模型，同一套 prompt 格式，同一个 `react()` 原语。区别只有两个——手上有哪些工具、看到哪些上下文。所以增益不可能来自「找了个更强的改写者」。

谁改谁，一句话：模型改外壳，外壳的改法由策略决定，策略被最外层改，最外层不可改。

组长每轮干三件事：

1. **挑起点**（seed selection）：从历史版本里挑一个做基础，并且必须写下一份假设，含四个字段——选哪个版本、为什么选它、预期改进什么、什么情况算这个假设被推翻（可证伪判据）。这一步逼着演化从瞎改变成有预测的搜索。
2. **改**（main evolution）：读代码、改文件、跑评测、看反馈、继续改。什么时候停由模型自己决定。
3. **入库**（commit selection）：不是只留分数最高的那个，而是维护一个多样性池，保留几条不同方向，每个版本还要附一段「它和前一版什么关系」的说明。

一个具体演进例子（BabaIsAI-Make，原报告 §5.4）：

- 第 1 轮：把外壳改成单次 react 重写 + 加上计划追踪。dev 分 0.222。
- 第 2 轮：加一个空间地图构建器，把 WIN 目标持久化下来。0.333。
- 第 3 轮：自动算目标位置 + 加 BFS 寻路。0.444。
- 第 4 轮：加自动推箱子机制和方向性兜底。
- 第 5 轮：LLM 感知的跨房间导航。0.556。

这里总监做的事是：把「LLM 定目标，BFS 负责走路」这个两层模式提炼成一条通用启发式，写进策略代码里；顺手把提交池容量从 1 扩到 3。

注意第 3 轮出现的 BFS 寻路——这是真正的算法组件，不是改 prompt 措辞。这一点很重要：如果演化出来的东西全是 prompt 微调，那「等价于多花推理算力」的指控就成立了。

## 为什么必须有一层「不许改」

递归自改进最经典的翻车方式：改写器有权改自己，那么「什么叫改得更好」这个判据也在它的权限里。系统于是从「优化任务表现」漂移成「优化自己的评分标准」。这就是 reward hacking 的架构版。

HSI 的处理是结构性截断。链条是：模型 → 外壳 → 策略 → 冻结锚点。到第三层结束，没有 meta-meta-evolver。

具体靠这些机制（原报告归纳成五条，本质是两类）：

- **递归截断类**：总监的执行逻辑从不可变模板加载，可改的只是「策略空间」，不是「执行策略的那段代码」；递归深度硬编码为 3。
- **能力隔离类**：目录级写权限——组长只能写外壳目录，总监只能写 `evolution/` 目录，越界写直接被拒；评测器和数据切分完全在可编辑范围之外；任务注入接口 `using_harness(agent, task)` 永久固定。

原报告有一个判断值得记住：真正防漂移的主力不是「不可修改的模板」，而是「评测器在系统外面」。即使策略被改成偏好某类候选，最后打分的还是外部评测器，分数骗不了人。

固定接口的另一个好处很实用：因为所有版本都通过同一个函数签名接任务，任意一代外壳都能热插拔——把目录换成另一个快照，调用方一行不改，而且所有版本都在同一评测协议下可比。

这是整篇论文最值得抄回自己项目的设计。

## 一个聪明的实验设计：干活时关掉思考

问题：外壳变好了，成绩涨了，怎么知道涨的是「外壳变好」还是「模型多想了几步」？

HSI 的做法极简：

- **干活时关掉 extended reasoning，temperature 设 0。**
- **改写时打开推理，reasoning effort 拉满。**

而且这个配置在所有阶段都不变——开发期评测、验证期评测、选最终版本、最后测试，全都是 thinking-off。所以任务执行侧的「每步能力上限」被钉死了，观察到的提升不可能来自推理时算力。

配套还有一道约束：所有任务交互必须过冻结模型。演化可以改外壳组件，但不能用外部搜索或非 LLM 策略把模型替换掉。没这条约束的话，演化很容易退化成「写一个不需要 LLM 的求解器」——那就不是在测外壳演化了。原报告提到 AutoHarness 那类 harness-as-policy 路线拿到 0.870 平均 reward，正是这个退化方向。

这条边界的准确说法是「LLM 必须留在决策回路里」，不是「不许有算法逻辑」。BFS 寻路是允许的，最终固化的模式就叫「LLM targets, BFS navigates」。

这是方法论上最干净的一处贡献，值得直接借鉴。

## 跑出来的效果

Setup A（同一批任务，但每次重新采环境种子），五个环境：

| 配置 | BabyAI | Crafter | TextWorld | MiniHack | NLE | 平均 |
| --- | --- | --- | --- | --- | --- | --- |
| 原始手写外壳 | 42.0 | 11.6 | 40.0 | 0.8 | 0.0 | 18.9 |
| 两层（关掉总监） | 77.3 | 36.4 | 46.0 | 5.8 | 0.0 | 33.1 |
| 三层（开总监） | 81.3 | 44.6 | 65.0 | 15.8 | 0.2 | 41.4 |

三层对原始外壳的增益：BabyAI +39.3，Crafter +33.0，TextWorld +25.0，MiniHack +15.0，平均 +22.5。

对照一下：HSI 的 41.4 和 Gemini-3-Flash 的 43.0、Grok-4 的 43.1 同一档。TextWorld 上 HSI 的 65.0 超过 Grok-4 的 62.9 和 Claude-Opus-4.5-Thinking 的 59.0。这是拿一个 Flash 级别的小模型换出来的。

**第三层到底值不值？** 拆开看：原始 → 两层是 +14.2，两层 → 三层是 +8.3。也就是说第三层贡献了总增益的约 37%。TextWorld 上更夸张：两层只拿到 +6.0，三层拿到 +25.0，第三层的贡献是前两层的三倍多。而且每一个被测的环境去掉第三层都下降。

NLE 是唯一的零增益：初始 0.0，三层 0.2。这个环境反馈太稀疏，演化拿不到任何有区分度的信号，循环空转。这个零点其实是论文最有价值的数据之一——它标定了这条路线的适用边界。

Setup B（BabaIsAI，20% 任务完全不可见的 held-out）：

| 子集 | 原始外壳 | 开发集最好 | 三层测试 | 两层测试 |
| --- | --- | --- | --- | --- |
| BreakStop | 0.0333 | 1.0000 | 0.9800 | 1.0000 |
| GoTo | 0.1818 | 1.0000 | 1.0000 | 0.9636 |
| Make | 0.0000 | 0.5556 | 0.3625 | 0.3375 |

导航类（BreakStop、GoTo）几乎打满，而且测试集全程不可见——这是对「外壳演化只是记住了具体修复」这个批评的有力反驳。Make 类（多步合成）开发集 0.5556 掉到测试集 0.36，标准差 ±0.3284 比差值本身还大，这是过拟合的直接量化。

## 别被结果骗了：三个要留意的地方

**一、「两个理论上界」名不副实。**

摘要说本文给出两个 bound。实际上正文里它们是「两条实践边界」——没有形式化陈述、没有推导、没有证明。原文自己的用词在「two fundamental limits」「two practical boundaries」「an empirical capability boundary」之间摇摆。

第一条叫反馈保真度边界，意思是：如果所有候选拿到的分数都差不多（比如 NLE 全是 0），那「选择」这个动作就不携带信息，整个演化退化成随机漂移。这是个信息论式的直觉论证，论文既没写成不等式，也没定义「保真度」怎么度量。

第二条叫骨干能力边界，意思是：改外壳改不出模型本身不具备的能力。这条的理论依据是**借来的**——引用另一篇论文（On The Statistical Limits of Self-Improving Agents）里关于 VC 维和 PAC 保证的结论，然后翻译成「任务需要的函数复杂度超过模型可达的 VC 维时，再怎么工程也补不上」。HSI 自己既没刻画自己的可达假设空间，也没估过 VC 维。

它们作为经验规律是有用的（部署前的筛子：环境能不能给有区分度的反馈？模型在这任务上基线是否非零？），但当成定理引用就错了。

**二、第三层的 37% 增益，有一个没控住的算力预算差。**

开总监意味着每轮多出最多 50 步 LLM 调用。论文没有做「等预算对照」——把这 50 步给组长而不是总监会怎样，完全没测。

所以严格说，这里证明的是「在总预算增加的前提下第三层值得」，不是「同预算下第三层更优」。这两句话的强度差很多。

更要紧的是：这个结论在 Setup B 上不成立。BreakStop 上两层（1.0000）反而优于三层（0.9800），Make 上两者差 0.025 而标准差 0.2 以上，只有 GoTo 上三层明显更好。原文只轻描淡写说两层变体「取得可比结果」，没有讨论这个不一致。合理的解释是：任务简单到两层就打满时，第三层没有发挥空间。

另外三层在 BabyAI 上的标准差反而更大（4.2 对两层的 1.2），Crafter 也是（3.2 对 1.6）。均值上去了，方差没下来，原文没讨论。

**三、最重要的架构主张，一个消融实验都没做。**

「外层锚点不可修改」是这篇论文最核心的设计贡献，也是它相对 HyperAgents（把元机制本身也变成可编辑代码）那类工作的全部差异所在。

但论文只论证了这个设计**为什么应该有用**，没有任何实验展示**去掉它会发生什么**——不会漂移吗？会 reward hacking 吗？会崩吗？不知道。纯设计论证，零实证。

顺带几个其他的规模问题：只用了一个模型、一个 benchmark；演化只跑 5 轮（对比 DGM 跑 80 轮、HyperAgents 跑 200 轮），而 Crafter 在第 5 轮就已经出现回退（第 4 轮 0.578 是峰值），说明设计空间非凸、演化不单调，5 轮的结论没法外推到长程；成本（API 调用量、token、耗时）完全没报。

## 如果我要用这个思路

1. **先建反馈，再建演化。** 如果目标任务上你的初始版本恒为 0 分，别开演化循环，先去造中间信号：部分完成度、子目标进度、单元测试、可解析的执行日志。NLE 的零增益就是反例。

2. **第一步只做一个最小注入接口。** 一个 `using_harness(agent, task)` 级别的函数签名就够撑热插拔了：内部随便改，调用方和评测协议零改动。但要补上 HSI 没写的部分——接口一致性校验（演化后不符合签名的版本应该在评测前被拒，而不是评测出 0 分）。

3. **用目录权限隔离，不要用 prompt 约束。** 在 system prompt 里写「不要修改评测代码」不可靠。HSI 的做法是越界写直接被机制拒绝。评测器和数据切分必须在可编辑范围之外，这是防 reward hacking 的主力。

4. **候选排序用 LCB，报告用原始指标。** 低预算下（每任务只跑 1-3 个 episode）用均值排序会持续选中「运气好的高方差版本」。HSI 排序用 $r = \mu - z\sigma/\sqrt{n}$（取 z=0.5），但所有报告的数字都是原始进度分。这两件事要分开，别混。

5. **强制每个候选带可证伪判据，提交池保留多条方向。** 写下「什么情况算我错了」把瞎改变成有预测的搜索，事后还能统计哪类假设先于大幅改进出现。提交池只留最优会让后续搜索无路可退——Crafter 第 5 轮的回退就是证据。

## 名词小词典

| 术语 | 大白话解释 |
| --- | --- |
| harness（外壳） | 围着模型的那一圈可执行代码：prompt、工具、记忆、状态管理、钩子、交互策略 |
| frozen backbone（冻结骨干） | 模型权重全程不动，不训练不微调，只改代码 |
| evolver（组长层） | 专职改写外壳的角色，看环境反馈决定怎么改 |
| meta-evolver（总监层） | 专职改写「改写策略」的角色，产出可复用的演化启发式 |
| frozen outer anchor（冻结外层锚点） | 最外层不可修改的执行模板，用来截断递归、防止系统改掉自己的评判标准 |
| thinking-on/off | 改写时开推理、干活时关推理，用来把「外壳变好」和「多想几步」分开 |
| held-out split | 演化全程碰不到的测试任务，用来验证是提炼了策略还是背下了答案 |
| LCB reward | 用「均值减去一点标准差」代替均值来排序候选，避免被运气好的高方差版本骗到 |
| evolution graph（演化图） | 记录所有提交过的外壳版本及版本间语义关系的图，供下一轮挑起点时推理 |
| probe | 不把完整历史塞进上下文，而是按需查询压缩摘要的机制 |
