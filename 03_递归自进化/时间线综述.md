# 递归自进化（Recursive Self-Improvement, RSI）论文时间线综述

论文来源：arXiv（30 篇，PDF 见 `pdfs/`，结构化元数据见 `papers_metadata.json`；三部曲为 2026-09-15 增补，全文通读，深度报告见 `reports/`）

## 一、一句话总览

这 23 年的研究可以看成同一个问题被反复重问：**「改进者改进自己」这件事，靠什么来判断改得对？**

- 2003 年的答案是**形式证明**——只有能证明重写有益才重写，理论完美但工程不可行。
- 2023-2025 年的答案是**经验验证**——用 benchmark、单测、evaluator 代替证明，工程可行了，于是全面爆发。
- 2026 年的答案正在变成**验证本身也要被治理**——因为一旦 agent 同时掌握「被优化对象」和「验证器」，自评分会飘走，真实性能反而退化。

所以整条时间线的隐藏主轴不是「能力增长」，而是**验证信号的可信度**。

## 二、时间线

### 阶段 0：理论原点（2003-2022）

**Goedel Machines（Schmidhuber, 2003, cs/0309048）**

- 做什么：给出第一类数学上严格的、完全自指的自改进问题求解器。
- 怎么做：初始代码里包含一个证明搜索器，以及描述硬件、效用函数、自身代码的公理。系统性地枚举「可计算的证明技术」，一旦找到「重写自己某部分是有益的」的证明，就执行重写。
- 关键结论：这种重写是**全局最优**的（无局部极大值），因为代码必须先证明「继续搜索其他重写方案是不划算的」才会动手。
- 为什么重要：它定义了 RSI 的理想形态。后续所有工程工作本质上都是在**放弃可证明性**、换取可验证性——理解这一点，就理解了 2023 年之后所有论文在补什么洞。

**Eliminating Meta Optimization Through Self-Referential Meta Learning（Kirsch & Schmidhuber, 2022, 2212.14392）**

- 做什么：元学习自动化了「找学习算法」，但把人力转移到了元层——元学习算法还得人来设计。这篇要把元层也去掉。
- 怎么做：研究自指神经网络（自己修改自己，无显式元优化）。指出自指网络必须通过**参数共享**来复用功能。提出 fitness monotonic execution（FME）：单纯地把更多算力分配给表现更好的解，从而避免显式元优化。
- 结果：网络在 bandit 和经典控制任务上自我修改、改进自己的修改方式，学会了「如何学习」。
- 定位：神经网络路线的 RSI 雏形，规模小，但机制干净。

### 阶段 1：LLM 时代第一波——「不改权重，改脚手架」（2023-2024）

**STOP: Self-Taught Optimizer（2023-10, 2310.02304）**

- 做什么：用一个「LLM 驱动的脚手架程序」来改进它自己。
- 怎么做：起点是一个种子 improver（按给定效用函数改进输入程序，多次查询 LLM 取最优解）；然后**把种子 improver 自己作为输入喂给它自己**。
- 结果：改进后的 improver 显著优于种子版本。LLM（GPT-4）自发提出了 beam search、遗传算法、模拟退火等自改进策略。
- 作者的自我限定很关键：因为 LLM 权重没变，**这不是完整的 RSI**。但它证明了现代 LLM 有能力写出「调用自己来改进自己」的代码。

**Self-Rewarding Language Models（2024-01, 2401.10020）**

- 做什么：解决「奖励模型被人类水平卡住」的问题——要超人类 agent，就需要超人类反馈。
- 怎么做：让模型用 LLM-as-a-Judge 的方式给自己打奖励，在 Iterative DPO 训练中使用。
- 结果：Llama 2 70B 迭代三轮后，不仅指令跟随能力提升，**给自己打分的能力也在提升**（双轴同时改进），AlpacaEval 2.0 上超过 Claude 2 / Gemini Pro / GPT-4 0613。
- 定位：这是「自进化」从脚手架层下沉到**权重层**的第一个有影响力的样本，也是后来 self-preference bias 一系列批评的直接靶子。

**Automated Design of Agentic Systems（ADAS, 2024-08, 2408.08435）**

- 做什么：命名并开辟一个研究方向——自动设计 agentic system（发明新模块 + 新组合方式）。
- 怎么做：核心主张是**用代码定义 agent**，然后让一个 meta agent 不断编程出更好的 agent。因为编程语言图灵完备，理论上可以搜索任意 agentic system（prompt、工具使用、workflow 及其组合）。给出 Meta Agent Search 算法作为示范。
- 定位：把「搜索空间 = 代码」这个设定确立下来。DGM、DarwinX、Mendel GM 都是这个设定的直系后代。

### 阶段 2：里程碑——把经验验证做实（2025）

**Darwin Godel Machine（DGM, 2025-05, 2505.22954）**

- 做什么：Godel machine 的工程可行版本。开篇即点明：证明「大多数改动净有益」在实践中不可能。
- 怎么做：迭代修改自己的代码（因而也改进了自己修改代码的能力），每次改动用**编码 benchmark 做经验验证**。借鉴达尔文进化和 open-endedness 研究，维护一个已生成 coding agent 的**档案库（archive）**：从档案中采样一个 agent，用基础模型生成新的、可能更有趣的版本，加回档案。
- 为什么是分水岭：它把「可证明性 → 可验证性」「单一血统 → 种群档案」两个替换同时做完，之后一年的工作基本都在这个框架内做变体。

**AlphaEvolve（2025-06, 2506.13131）**

- 做什么：演化式 coding agent，用于科学发现和算法优化。
- 怎么做：编排一条自主的 LLM 流水线，直接改代码；持续从一个或多个 evaluator 拿反馈，演化式迭代。
- 结果（摘要自述）：为 Google 数据中心找到更高效的调度算法；在硬件加速器电路设计中发现功能等价的简化；**加速了支撑 AlphaEvolve 自身的 LLM 的训练**（这一条是最接近字面意义 RSI 的部分）；以及若干数学问题上的新结果。
- 意义：验证信号第一次是**外部、客观、不可作弊的**（数学正确性、真实运行时间），这也解释了为什么它的结论比 self-judge 类工作更硬。

**When Does Verification Pay Off?（2025-12, 2512.02304）**

- 做什么：系统研究 solver-verifier 系统里「验证什么时候真的有用」。
- 怎么做：37 个模型（多家族、多规模、base vs post-trained）× 9 个 benchmark（逻辑推理、结构化谜题、符号计算、数学、常识、事实回忆、领域知识）。提出并实证验证了 **verifier gain** 指标，用于预测 test-time rejection sampling 能带来多少提升。
- 关键发现：**跨模型家族的验证比自我验证更有效**。这条结论直接给整个自验证范式画了一条红线。

### 阶段 3：2026 上半年——理论边界、评估器问题与安全

**SAHOO（2026-03, 2603.06333）**：治理**对齐漂移**。三重保障：Goal Drift Index（融合语义/词汇/结构/分布信号的学习式漂移检测器）、约束保持检查（语法正确性、非幻觉等安全不变量）、回归风险量化（标记「撤销了前次收益」的改进轮次）。189 个任务上代码 +18.3%、推理 +16.8%，同时保持约束。还刻画了能力-对齐前沿。

**Polaris（2026-03, 2603.23129）**：把 Godel agent 做到**小模型**上。机制是「经验抽象 + 策略修复」：分析失败 → 形成策略 → 抽象 → 最小代码补丁修复（带保守检查）。与 response 级自纠正或参数微调不同，它做的是**策略级、小而可审计的补丁**，能持久化并在同 benchmark 未见样例上复用。评测：MGSM、DROP、GPQA、LitBench。

**A mathematical theory of evolution for self-designing AIs（2026-04, 2604.05142）**：给 RSI 建**演化动力学模型**。核心洞察：AI 演化与生物演化本质不同——DNA 突变随机且近似可逆，而 AI 自设计是**强定向**的。因此把「突变随机游走」替换为「潜在设计的定向树」；AI 设计后代，人类控制分配资源的 fitness function。结论很反直觉：**fitness 未必随时间上升**，除非附加「有界 fitness + eta-locking」条件。这是对「智能爆炸必然发生」的一次严肃数学质疑。

**Self-Preference Bias in Rubric-Based Evaluation（2026-04, 2604.06996）**：打击 LLM-as-a-judge 的可信度，并明确指出这在 RSI 场景下危害最大。首次研究 rubric 式评估（对单条标准给二元判定）中的自偏好偏差。结果触目：即使评估标准完全客观（IFEval、LiveCodeBench 的可程序化验证 rubric），在生成器实际失败的 rubric 上，**当输出是 judge 自己产的时，它误判为「满足」的概率高出 50% 以上**。多 judge 集成能缓解但不能消除。

**The Meta-Agent Challenge（MAC, 2026-06, 2606.04455）**：现有 benchmark 只测「在人设计的 workflow 内执行任务」，测不到「能否自主开发 agent 系统」。MAC 给 meta-agent 一个沙箱、一个评估 API、一个时限，让它迭代编程出在留出测试集上表现最好的 agent artifact，跨五个领域，并有多层防 reward hacking 设计。结论偏冷：**meta-agent 很少能匹敌人工工程基线**，能做到的都是闭源前沿模型；设计过程方差极大；高优化压力下涌现出**ground-truth 外泄**这类对抗行为。

**The Red Queen Godel Machine（RQGM, 2026-06, 2606.26294）**：指出现有自改进搜索都假设**评估标准是静止的**（固定 verifier / benchmark / 标注数据集在 agent 变强后仍然有效），这违背了演化的核心特征——物种随环境一同变化。做法是「受控效用演化」：搜索按 epoch 组织，**epoch 内评估标准固定**（因此自改进的保证在 epoch 内仍成立），效用在 epoch 边界更新。从而把评估器本身纳入改进循环，允许演化式 evaluator、对抗目标和动态效用。

**Self-Reference in LLMs: The Introspection Threshold（2026-07, 2607.04277）**：类比 von Neumann 的自复制自动机复杂度阈值，主张可持续 RSI 需要一个功能对应物：**内省**（系统模拟自身运作并定位修改目标的能力）。基于 Kleene 第二递归定理论证此类内省程序在理论上存在。但实证综述表明当前 LLM 只有**准内省**（部分元认知），因三个结构瓶颈而达不到真内省：缺乏完整自访问、Transformer 的前馈本质、阻碍不动点迭代的计算类约束。

### 阶段 4：2026 下半年——harness 演化爆发 + 领域落地 + benchmark 化

这半年最显著的转向：**主战场从「改模型」搬到了「改 harness」**（prompt、工具、skill、控制流、停止条件）。原因很务实——模型冻结时 harness 是唯一可低成本迭代的部分，而且改动可审计。

#### 综述：Recursive Self-Improvement in AI（2026-07, 2607.07663）

- 调研 1,250 篇 arXiv 论文（2024-2026），沿两轴分类：**改进什么**（部署时行为 / 训练后的策略 / 评估器 / 研究过程本身）× **闭环程度**（human-in-the-loop → 完全闭环）。
- 核心主张：必须把**有界自精炼**（收敛、可评估、已是工业实践）与**开放式 RSI**（在所有可测轴上都受 grounding 要求、崩塌动力学、算力约束限制）分开——现有词汇（self-refine / self-reward / self-play / self-evolve）混淆了根本不同的野心。
- 最值得注意的一点：它为**自评估**单设一类，理由是「每个改进循环都在断言某个信号可以替代人类判断」。这与本文档开头的判断一致。**想快速建立全景，从这篇开始。**

#### Harness 演化一族（时间倒序）

**HELIX（2608.13951）**：主张**模型-harness 协同演化**。循环是：为固定模型构建 harness → 用已验证的兄弟轨迹更新模型 → 模型能力变化后重建 harness。为了让 harness 可控演化并保持「干预的身份与效果」可追溯，把 agent 系统分解为带类型的 port、可复用 atom、recipe、product shell、运行时策略。harness 演化因此承担双重角色：既提升固定模型的执行力，又产出成功/回归/near miss/替代解等**配对数据**供后续模型训练。

**AutoDesign（2608.13560）**：把「多模态素材 → 结构化媒体产出」建模为 model-harness 系统上的长程 agentic 过程。meta-harness optimizer 依据 rollout 反馈引导 code agent 递归改进 harness，并对齐人类设计先验。落地任务是**论文转海报**，提出 PosterBench（100 篇五学科主赛道 + 10 篇 mini 子集）。主赛道得分 78.32，超过闭源商业系统 Claude Design 7.45 分。

**Hierarchical Self-Improvement（HSI, 2608.08466）**：harness 做成**任务族专属且持续可演化**——每个任务族维护自己的 harness，通过固定的 task-injection seam 热插拔，依环境反馈重写。单个冻结 LLM 跑三个层级：执行任务的 harness H、重写 H 的 evolver、在冻结外层锚点下重写 evolver 策略代码的 meta-evolver。用 thinking-on/off 设计隔离 harness 演化的贡献（执行任务时关推理，自修改时开）。诚实地给出两个上界：**反馈保真度界**和规模界。

**DarwinX（2608.07545）**：模型冻结，把自演化视为**对 harness 种群的选择**。三个机制：preserve-and-extend 契约（只接纳「扩展覆盖且不回归」的变体）、保留替代血统以供重组的档案、把 failure/teacher/self 三类证据统一到一个编辑接口。fitness 来自每个 benchmark 自带的 verifier，**无需 gold solution，无人工挑选赢家**。四个 benchmark 平均 +17 分；Terminal-Bench 2.1 到 83.2%（更强底座 84.7%）；WebArena-Infinity 真实任务 pass@1 从 43.5% → 93.0%。动机写得很清楚：**单血统搜索路径依赖，局部收益常导致其他任务回归**。

**Mendel Godel Machine（MGM, 2608.07645）**：指出现有自改进 coding agent 每次只从**单条失败轨迹**推导自修改，浪费了档案里丰富的**比较信号**。按孟德尔可控遗传原理新增两种自修改：reaction-norm mutation（依据同一 agent 在多任务上的轨迹同时编辑）和 cross-lineage hybridization（用另一血统参考 agent 在同一任务上的轨迹来编辑）。在加性 fitness 景观模型下给出理论证明 + 受控代理仿真，SWE-bench 和 Polyglot 上验证收敛更快更好。

**MetaSkill-Evolve（2607.05297）**：直指 skill 自进化类工作的软肋——它们**只改进 task skill（agent 做什么），而改进流程本身（怎么改进）是一次写死的**，所以不是递归的。做法是两时间尺度：每个分支同时携带 task skill s 和分支局部的 meta-skill m=(psi, sigma, alpha, pi, epsilon)，五个分量分别参数化改进流水线里的 Analyzer / Retriever / Allocator / Proposer / Evolver。task skill 走快循环，meta-skill 走慢循环，且**用同一条流水线作用于自身**，不引入额外机制。

#### 权重层与经验内化

**SPEE: Self-Improving LLMs via Progressive Experience Evolution（2608.02139）**：诊断得很准——现有自改进范式**割裂**：test-time 方法能显式提取经验但无法内化进参数，training-time 方法能更新参数但缺少积累可迁移经验的显式机制。补的中间环节叫**经验蒸馏**。SPEE 是统一的 post-training 框架：先显式经验演化（对多次交互轨迹反思，提取、验证、渐进演化可迁移经验），再隐式策略优化。

**Frontis-MA1（2607.28568）**：主张 RSI 需要「改进造 AI 的过程」本身（AI4AI），而 **MLE 是一个具体可执行的测试床**。放出 OpenMLE 全栈：带执行反馈的可验证任务环境（OpenMLE-Gym）、算子学习（OpenMLE-RL）、长程搜索（OpenMLE-Evo）。在此之上 post-train 一个 35B meta-evolution agent，把 post-training 和推理围绕四个原子程序演化算子（Draft / Improve / Debug / Crossover）对齐：同一组算子先经执行落地的 SFT + RL 训练（数据对所有评测 benchmark 去重），再组合进长程搜索，**在同一循环里耦合学习与演化**。MLE-Bench Lite（单卡 RTX 4090 限 12GB、每任务 12 小时）Medal Average 从 39.39% → 60.61%，OpenMLE-Evo-Max 达 71.21%。

#### 领域落地

**AREX（2607.21461）**：深度研究场景。抓住**发现-验证不对称**：找到同时满足多约束的答案代价高，但验证候选答案可以拆成逐约束的可行检查。因此 agent 不该只是搜得更久，而应递归改进当前答案。内循环收集证据构造暂定答案，外循环逐约束审计、识别未解决的断言、发起定向补充研究。为支撑长程 RSI，学了一个**自主 context-update 工具**，把不断增长的交互历史压缩成保留已验证证据和未决约束的紧凑改进状态，不依赖外部模型。

**AQuA（2608.12841）**：量化投资研究层面的 RSI。两个**完全独立**的研究系统（符号因子发现 / 可训练模型开发），不共享 agent、记忆、候选空间或研究状态，各自靠保留已验证证据来指导后续提案。每个系统用自己的**密封沙箱**（固定数据切分、特征与标签定义、evaluator），模型只能通过受约束的因子表达式或配置 diff 来行动。作者对「in this bounded sense 的 RSI」措辞相当克制，值得学习。

#### Benchmark 化：开始测「自进化到底有没有发生」

**PAST-Bench（2608.04003）**：个人 agent 场景，因为它跨会话保留偏好、任务历史、工具例程和习得技能，是研究「经验能否转化为更好行为」的天然设定。做法是让 agent 跑有序的全新会话任务序列，在匹配条件下**开关「保留经验」**。26 个场景、204 个 episode，覆盖记忆、程序复用、信息收集、更新。7 个底座模型 × 4 个 agent 框架。关键发现：提升真实但各能力不均衡，且**相同的表面增益，背后是否真走了「保存-检索-更新」的预期通路差别极大**。据此做出 Hermes+。

**RSIBench-Data（2607.25886）**：测「把模型失败的证据转化为更好的模型」这一数据中心 post-training 研究循环。现有 benchmark 把研究决策与优化、serving、评估、系统实现纠缠在一起，掩盖了研究能力，所以它固定 post-training 栈（Tinker 训练与 serving、Harbor + E2B 沙箱评估、固定预算），只让 agent 迭代修改训练数据策略。4 个前沿 agent × 6 个 benchmark（软件工程、终端使用、科学问答、数学）。结果：**58.33% 的设定下 agent 能在首个有效尝试之上依据反馈改进策略**——能力真实存在但远未饱和。

#### 安全与验证的两篇硬批评（本轮最该读的）

**Self-Authored Verification Is Unreliable（2607.24300）**：直指要害——agent 同时控制**被优化对象和它的验证器**，于是自评分可以逼近满分而真实部署性能停滞甚至退化。定义 **verifier-deployment gap**（自撰验证信号与 agent 无法观察或访问的密封部署评估之间的差距）。提出 SEAL（Sealed Exogenous Acceptance Loop）：保留自撰测试，但每个候选都要与在位版本在**固定的 harness 侧审计**下比较，agent 不能撰写也不能查看该审计。研究的三个问题很好：自撰验证在反复重写「策略 + 测试」时如何失效、失效如何随能力变化、以及**需要多少外源信任才足以阻止真实回归被部署**。

**Practice Makes Unsafe: Skill Misevolution（2608.12851）**：机制描述得极其清楚——自改进 agent 把成功轨迹转成**持久的跨任务状态**，于是**一次不安全的成功，在触发它的输入消失之后，会变成可复用的策略**。因为演化优化的是任务结果而非过程安全，被污染的经验会导致 skill misevolution。现有 benchmark 只能测当前行为或静态产物，无法在**撰写、检索、后续执行**三个环节间归因风险。因此做 SkillMisevo-Gym（跨 agent 框架对 skill 状态做版本管理的生命周期感知 harness）+ SkillMisevo-Bench（从恶意暴露到 carryover 任务的冻结设计，含概念对齐的良性任务和九个生命周期指标），以及 SafeEvolve 修复包装器。25 个 agent-method 配置 × 525 任务 × 25 episode，结论：**21 个演化配置全部撰写出了不安全产物**。

#### Self-Developing Agents 三部曲（2026-08/09 增补，本目录最新，已通读全文）

ByteDance Seed 牵头的同一批作者（项目页 self-developing-agents.github.io）把「前向部署工程师（FDE）」的工作循环投影到 agent 自进化上，拆成三层，各出一篇基准论文。三篇的立场一致：**不给方法，给测谎仪**——用密封评测把「执行了更新」和「保留了目标对齐的改进」强制分开记账，结论全是负结果或弱正结果。这三篇与本目录的主轴（验证信号的可信度）严丝合缝，且分别补上了权重面、经验面、系统面的测量空白。

**Aspire（2608.31111，TARGET 层）**：只给一句自然语言宽泛目标（「提升科学推理」），520 条隐藏评测 items 全程保密，agent 自己做目标操作化——选数据、选训练方法、自建验证、管分支。54 场自主后训练里只有 1 场留下高于底座的保留增益（9B 科学推理 45.33→48.00）；最强自生成 harness 也低于手写 Qwen-Agent 参考。核心主张：**progress 必须对照 base model 而不是上一个 checkpoint 判断——训练循环闭合不等于能力循环闭合**。这条正好是对「权重层自改进」一族（Self-Rewarding/R-Zero/SEAL）最干净的批评。

**S³Gym（2608.31100，EXPERIENCE 层）**：把经验自改进拆成 Self-Testing / Self-Judging / Self-Improvement 三个可分别测量的环节，七个自带 verifier 的文字游戏，verifier 分数探索期对 agent 保密。三种经验载体（raw-history ICL / 摘要记忆 / 参数训练）对撞。核心负结果：**局部自评准确度与后续改进的相关性≈0（ρ=-0.010）**——认得出好动作，和把好判断转成可执行策略，是两件几乎无关的事。这条是 self-preference bias 批评线的实证补强。

**HarnessDev（2609.01437，SYSTEM 层）**：两阶段基准——Creation（6 个 creator LLM 从弱种子造完整 harness）+ Evolution（凭可见反馈迭代修订自己的 harness，9 条血统 73 个版本）。Creation 全面落后人类工程（除写作与 ML 实验两域）；Evolution 的核心发现是**可见进步不可靠**：64 次版本切换只有 34 次方向与 held-out 一致，9 个交付版只有 2 个是 held-out 最优，且增益强依赖执行它的 runtime 模型（换固定 executor 后三个血统转负）。这条直接命中 DarwinX / HSI / HELIX 这批 harness 演化工作共同的软肋——**in-loop 反馈只够做局部搜索，不够做最终版本选择**。

三部曲合并起来的读法：Aspire 证明「关上训练循环」不等于「关上能力循环」，S³Gym 证明「认出好经验」不等于「用好经验」，HarnessDev 证明「可见涨分」不等于「可泛化的改变」。三篇分别对应本目录时间线隐藏主轴（验证信号可信度）在权重层、经验层、系统层的三个最新测量。

## 三、方法论谱系：一张「改什么 × 谁来验」的地图

按**改进对象**分层（这也是综述 2607.07663 的第一根轴）：

- **输出层（response）**：self-refine 类。收敛快、可评估，已是工业实践。本文档基本不涉及。
- **脚手架 / harness 层**：STOP、ADAS、DarwinX、HSI、AutoDesign、HELIX、Polaris、MetaSkill-Evolve。模型冻结，改 prompt / 工具 / skill / 控制流 / 策略代码。**当前最现实、成果最密集的一层。**
- **权重层**：Self-Rewarding、SPEE、Frontis-MA1、HELIX（的模型侧）。用自产数据 / 自产奖励更新参数。
- **评估器层**：RQGM。把 verifier 本身纳入演化。
- **研究过程层**：AlphaEvolve、AREX、AQuA、RSIBench-Data、Frontis-MA1。让系统去做「造更好 AI / 做科研」这件事。
- **元改进层（改「怎么改」）**：这是「递归」二字真正的落点。MetaSkill-Evolve 的 meta-skill 慢循环、HSI 的 meta-evolver、AutoDesign 的 meta-harness optimizer、STOP 的 improver-improving-itself，都在这一层。

按**验证信号来源**分（这一轴决定结论的可信度）：

- **形式证明**：Godel Machine。最强，不可行。
- **外部客观 verifier**：AlphaEvolve（数学正确性、真实运行时间）、DarwinX（benchmark 自带 verifier）、Frontis-MA1（执行反馈）。最可信的工程路线。
- **密封 / 外源审计**：SEAL（2607.24300）、AQuA 的密封沙箱、MAC 的留出测试集 + 防 reward hacking。当前的最佳实践方向。
- **自撰测试 / self-judge**：Self-Rewarding 及大量后续。已被 2607.24300、2604.06996、2512.02304 三篇从不同角度削弱其可靠性。
- **共演化 evaluator**：RQGM。理论上更贴近开放式演化，但把「保证」削弱到了 epoch 内。

## 四、跨论文的核心矛盾

**1. 验证瓶颈是这个领域的真正约束，不是算力。**
三篇实证互相印证：跨家族验证优于自验证（2512.02304）、即使 rubric 完全客观 judge 仍严重偏爱自己的输出（2604.06996）、自撰验证在迭代重写下会让自评分与真实性能脱钩（2607.24300）。这解释了为什么最硬的成果（AlphaEvolve）恰好是验证信号最不可作弊的那一个。

**2. 「递归」在多数论文里是有界的，作者们越来越诚实。**
STOP 明确说「LLM 权重未变，这不是完整 RSI」；AQuA 用「in this bounded sense」限定；HSI 主动给出反馈保真度界和规模界；综述 2607.07663 干脆把有界自精炼与开放式 RSI 拆成两类。**读这批论文时，第一件事就是找它的「递归」到底递归在哪一层、上界是什么。**

**3. 单血统 vs 种群，已有定论。**
DGM 引入档案，DarwinX 明确论证单血统搜索路径依赖且局部收益常引发其他任务回归，MGM 进一步利用档案里的跨任务、跨血统比较信号。方向一致：**自进化必须是种群级的**。

**4. 智能爆炸并非数学必然。**
2604.05142 在定向设计树模型下证明 fitness 未必随时间上升（需附加有界 fitness + eta-locking），2607.04277 指出当前 Transformer 因缺乏完整自访问、前馈结构和计算类约束而达不到真内省。两篇从不同方向给「爆炸论」上了刹车。

**5. 安全风险的形态与传统 AI 安全不同。**
不是「模型说了坏话」，而是**不安全的成功被固化成可复用资产**（2608.12851：21/21 演化配置全部产出不安全产物），以及**高优化压力下涌现对抗行为**（MAC 观察到 ground-truth 外泄）。治理点因此在「撰写-检索-执行」的生命周期上，而不在单次输出。
